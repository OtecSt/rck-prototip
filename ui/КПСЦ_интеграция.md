# КПСЦ · Интеграция карты потока в «Агент-цех»

> v01 от 04.08.2026 · Для интегратора UI (этап 2 «Диагностика»).
> Ядро: `Прототип/vsm_karta.py` (stdlib only, CLI). Проверка: `результаты/проверка_кпсц_v01.md`.

## 1. Размещение в UI

Карточка **«Карта потока (КПСЦ)»** — на этапе 2 «Диагностика», **рядом с карточкой «Поиск узкого места»** (та же строка сетки или вкладкой под ней). Состав карточки:

- кнопка **«Построить карту»**;
- область превью: SVG **inline** (вставить ответ как `innerHTML` контейнера — ядро возвращает самодостаточный `<svg>` с собственными `width/height/viewBox`; обернуть в контейнер с `overflow-x: auto`);
- кнопка **«Скачать .svg»** (Blob из того же ответа, имя файла `кпсц_<поток>_<дата>.svg`);
- строка итогов из `итоги_json` (ΣVA, ВПП, доля ценности, статус пробелов).

**Ключевое правило: данные не вводятся дважды.** Карта строится из ТОГО ЖЕ JSON таблицы операций, что и «Поиск узкого места» (Спека № 1: `поток`, `операции[].имя/тц_мин/впп_сек/производительность_т_ч/возврат_пкт/запас_перед_шт`, `впп_итого_сек`, …). Перед POST берём текущее состояние таблицы этапа 2 и сериализуем в тот же контракт, что для `/api/uzkie` (или как он назван в app.py).

## 2. Эндпоинт

```
POST /api/vsm
Content-Type: application/json
```

Тело = JSON таблицы операций (спека № 1) + опционально:

```json
{
  "...": "поля спеки № 1 как есть",
  "glavnoe": "Процесс фасовки на одном выбойном аппарате (фасовка в мешок 30 кг)"
}
```

- `glavnoe` — имя главного узкого места **из последнего расчёта** «Поиск узкого места» (поле `главное.имя` результата ядра `узкие_места.py`). Если расчёта ещё не было или главное не подтверждено — поле не передаём: карта построится без подсветки, это не ошибка.
- Имя должно совпадать строка-в-строку с `операции[].имя`, иначе подсветки не будет (ядро не ругается).

Ответ 200:

```json
{
  "svg": "<svg xmlns=...>...</svg>",
  "итоги_json": { "поток": "...", "дата": "2026-08-04", "операций": 11,
    "сум_тц_сек": 78.1, "сум_nva_сек": 83709.3, "впп_сек": 83765,
    "доля_ценности_пкт": 0.1,
    "главное_узкое_место": "Процесс фасовки ...",
    "пробелы": ["запасы перед операциями", "ВПП не по всем операциям", "..."] }
}
```

Ответ 422 — если вход отклонён ядром (нет операций, пропуск имени, Тц ≤ 0): `{"ошибка": "..."}` — показать текст пользователю как есть.

### Реализация на бэке (app.py, 5 строк логики)

```python
from vsm_karta import строить_svg          # ядро лежит в Прототип/
svg, итоги = строить_svg(данные, glavnoe=тело.get("glavnoe"))
return {"svg": svg, "итоги_json": итоги}
```

Ядро детерминировано и быстрое (мс) — отдельный worker/очередь не нужны.

## 3. Хранение в истории

В таблицу истории расчётов (там же, где прогоны узких мест) добавить запись типа `vsm`:

- `тип`: `"vsm"`
- `вход_json`: тело запроса (как у узких мест)
- `итоги_json`: объект из ответа (маленький, храним целиком)
- `svg`: НЕ хранить в БД целиком — при надобности сохранять файлом в `результаты/` и класть путь; перестроить из `вход_json` можно всегда (идемпотентность проверена).

## 4. UX-детали

- Если `итоги_json.пробелы` не пуст — над картой показать плашку «СТАТУС: С ПРОБЕЛАМИ» (она уже отрисована в шапке SVG — дублировать крупно не надо, достаточно тултипа на «?»).
- Пустая таблица / незаполненные Тц → кнопку «Построить карту» дизейблим с подсказкой «заполните имя и Тц хотя бы у одной операции».
- Длинные имена операций ядро переносит само (≤ 30 симв., ≤ 4 строки) — в UI дополнительной обработки не требуется.
- Палитра уже UI-совместимая (терракота/крем), CSS-переопределений не нужно.

## 5. Что НЕ делает интеграция (границы)

- Не редактирует карту (просмотр + скачивание только).
- Не считает узкое место сама — берёт готовое из последнего расчёта; нет расчёта → карта без подсветки.
- Не шлёт SVG наружу; скачивание — локальный файл пользователя.
