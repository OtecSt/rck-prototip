    Настоящий документ определяет порядок работы пользователя в веб-сервисе «Ведение проектов · РЦК» — рабочем инструменте РЦК-консультанта для ведения проекта по улучшению по маршруту МУ-65-2024.

    Редакция 3.1 (интерфейс v2.2) · 7 августа 2026 г. · Для внутреннего использования

    1. Назначение и область применения

    1.1. Настоящий документ является руководством пользователя веб-сервиса «Ведение проектов · РЦК» (далее — сервис). Сервис оцифровывает методологию ведения проекта по улучшению Федерального центра компетенций (ФЦК): маршрут МУ-65-2024 «Реализация проектов по улучшениям» от открытия проекта до протокола закрытия.

    1.2. Сервис выполняет расчёты показателей по официальным формулам (МУ-66-2024 «Показатели проектов повышения производительности труда», МР-09-2022 «Оценка экономического эффекта от реализации мероприятий», редакция № 2) и формирует документы: пакет организационно-распорядительной документации (ОРД), разворот целей SMART, отчёт по узким местам потока создания ценности, карту потока создания ценности (КПСЦ), расчёт экономического эффекта (ЭЭ), справку ФЦК по форме 1.4, план мероприятий по шаблону Приложения № 4 МР «Решение проблем» и протокол выполнения мероприятий.

    1.3. Все расчёты выполняются детерминированным расчётным ядром. Один и тот же набор входных данных всегда даёт один и тот же результат. Каждая итоговая величина в отчёте приводится с подстановкой значений в формулу. Результаты расчётов воспроизводимы и пригодны для представления на защите проекта.

    1.4. Документ предназначен для консультантов региональных центров компетенций (РЦК), руководителей проектов предприятий и специалистов, выполняющих тестирование сервиса.

    2. Системные требования и доступ

    2.1. Системные требования

    2.1.1. Для работы с сервисом требуется персональный компьютер с современным браузером (Chrome, Edge, Firefox, Safari актуальных версий). Установка дополнительного программного обеспечения на стороне пользователя не требуется.

    2.1.2. Для открытия выгружаемых документов формата docx требуется редактор Word; для файла справки ФЦК формата xlsm — Microsoft Excel с разрешённым выполнением макросов (пересчёт итоговых значений выполняется Excel при открытии файла).

    2.1.3. Адрес доступа к сервису и учётные данные направляются пользователю владельцем сервиса отдельным сообщением.

    2.2. Учебные данные

    2.2.1. В базе сервиса размещены учебные проекты («ОКЗ — экзамен волна 3», «Кушкуль — экзамен волна 3», «Тест интеграции в2» и др.). Данные учебных проектов обезличены и синтетичны; они предназначены для ознакомления с историей прогонов и сравнением. Рабочий проект создаётся отдельно (п. 4.1).

    3. Обзор интерфейса

    3.1. Режимы интерфейса

    3.1.1. В шапке страницы расположен переключатель режимов «Простой старт» и «Полный режим». Выбранный режим запоминается браузером; переключение не приводит к потере введённых данных.

    3.1.2. Режим «Простой старт» открывается по умолчанию и содержит одну карточку — «Поиск узкого места» — с демо-кнопкой «ОКЗ (комбикорм)». Режим предназначен для первого ознакомления с сервисом. Кнопка «Перейти к полному режиму» открывает полный состав этапов и инструментов.

    3.1.3. Режим «Полный режим» отображает боковое меню этапов проекта и все инструменты, описанные в разделе 5.

    3.2. Боковое меню этапов

    3.2.1. В левой части экрана расположено боковое меню этапов проекта по маршруту МУ-65: «0. Предстарт», «1. Открытие», «2. Диагностика», «3. Цель и план», «4. Внедрение», «5. Закрытие», а также пункт «Помощь». Каждый пункт снабжён иконкой и краткой подсказкой о содержании этапа.

    3.2.2. Щелчок по пункту меню открывает соответствующий этап; на экране одновременно отображается один этап. У пунктов меню отображаются бейджи с числом сохранённых прогонов по инструментам этапа (при выбранном проекте).

    3.2.3. Пункт «Помощь» открывает встроенную методичку пользователя (настоящий документ в сокращённом виде) со ссылками на разделы по каждому инструменту.

    3.3. Общие правила работы карточек инструментов

    3.3.1. Автоматический пересчёт. В инструментах «Поиск узкого места», «Цели SMART», «ЭЭ-калькулятор» отчёт пересчитывается автоматически через полсекунды после изменения любого поля. Отдельная кнопка «Рассчитать» отсутствует.

    3.3.2. Пустое поле — отсутствие данных, а не ошибка. Инструмент рассчитывает показатели, для которых достаточно введённых данных; недостающие данные перечисляются в блоке «домерить». Подстановка нулевых значений не выполняется.

    3.3.3. Валидация ввода. Ячейка с нечисловым значением подсвечивается красным («не число») и блокирует пересчёт с перечнем проблем (например: «строка 3, колонка "Тц, мин": "двадцать" — не число»). Незаполненная обязательная ячейка подсвечивается янтарным («не заполнено»). Допускаются десятичная запятая и пробелы-разделители разрядов.

    3.3.4. Плашка «отчёт устарел». Если после получения отчёта введённые данные изменены так, что расчёт стал невозможен (не исправлены подсвеченные ячейки), область отчёта приглушается и отображается плашка «Отчёт устарел — исправьте подсвеченные данные, отчёт пересчитается автоматически».

    3.3.5. Подтверждение демо-данных. Если в форме имеются введённые пользователем данные, нажатие демо-кнопки вызывает запрос подтверждения («Заменить введённые данные демо-примером?»). При отмене введённые данные сохраняются.

    3.3.6. Предупреждение при закрытии. При закрытии вкладки с несохранённым вводом браузер выводит предупреждение. Автоматическое сохранение черновика не предусмотрено; перед завершением работы сохраните прогон (раздел 6).

    4. Базовые понятия: проект, прогон, метка, контекст

    4.1. Проект

    4.1.1. Проект — запись в базе сервиса: название, предприятие, пилотный поток создания ценности. Создаётся кнопкой «Новый проект» в шапке страницы. Обязательным является только название; поля «предприятие» и «поток» следует заполнить при создании, поскольку они используются проверками контекста (п. 4.4).

    4.1.2. Текущий проект выбирается в выпадающем списке шапки; выбор запоминается браузером. Индикатор в шапке отображает «Проект: название · предприятие · поток» либо «проект не выбран».

    4.1.3. Без выбранного проекта доступны все расчёты; недоступны сохранение прогонов, история, сравнение и автоматическая подстановка данных между инструментами.

    4.2. Прогон

    4.2.1. Прогон — сохранённый в проекте расчёт одного инструмента: входные данные, отчёт, ключевые итоги, автор, дата, комментарий. Сохранение выполняется кнопкой «Сохранить прогон в проект», имеющейся в каждом инструменте.

    4.2.2. При сохранении браузер передаёт на сервер только входные данные; сервер повторно выполняет расчёт через расчётное ядро и сохраняет результат. Подмена итоговых значений исключена.

    4.2.3. Прогон является неизменяемым: редактирование и удаление не предусмотрены. При ошибочном вводе создайте новый прогон с поясняющим комментарием (например: «перезамер, исправлен Тц дозирования»). История проекта ведётся по принципу лабораторного журнала.

    4.3. Метки «до» и «после»

    4.3.1. При сохранении прогона ему может быть присвоена метка «до» или «после» (либо прогон сохраняется без метки). Метки используются при сравнении и при подстановке данных: например, в протокол закрытия экономический эффект подставляется из самого свежего прогона ЭЭ-калькулятора; если этот прогон не имеет метки «после», сервис выводит соответствующее предупреждение.

    4.3.2. Пример применения: в марте сохранён прогон диагностики с меткой «до»; в июне, после внедрения мероприятий, сохранён повторный замер с меткой «после». Отметьте оба прогона в истории и нажмите «Сравнить до/после» — будет сформирован дельта-отчёт об изменении узкого места, долей ВПП и производительности.

    4.4. Контекст

    4.4.1. Контекст — пара «предприятие · поток». Сервис предотвращает смешение данных разных потоков создания ценности:

    • если при сохранении прогона предприятие или поток во входных данных расходятся с карточкой проекта, прогон сохраняется с пометкой «контекст расходится» и предупреждением;
    • при автоматической подстановке (в ЭЭ-калькулятор и протокол закрытия) значения из прогонов другого потока не подставляются; сервис выводит объяснение отказа;
    • если форма начата при одном проекте, а сохранение выполняется в другой, отображается запрос подтверждения «Данные вводились для другого контекста. Сохранить?».

    4.4.2. Правило организации работы: один проект — один поток. Различные потоки одного предприятия ведутся отдельными проектами.

    5.5.6. Выгрузка справки ФЦК. Кнопка «Скачать справку ФЦК» формирует заполненный файл формата .xlsm по форме ФЦК «1.4 Справка» (ветка «концевой серийный поток») на основании текущего ввода формы. Расчётные ячейки и валидаторы шаблона не перезаписываются; пересчёт итоговых значений выполняется Excel при открытии файла. Имя файла формируется автоматически: «1.4 Справка_ЭЭ_<предприятие>_<дата>.xlsm». При отсутствии обязательных данных сервис возвращает перечень ошибок вместо файла.

    5.6. План мероприятий (этап «Цель и план»)

    5.6.1. Инструмент превращает находки диагностики в обоснованный и квантифицированный план мероприятий по шаблону Приложения № 4 МР «Решение проблем». Методологическая опора: МР «Решение проблем», МУ-65-2024, Приложения № 4, 6 (оценка рисков) и № 8 («Матрица приоритезации проблем»). Применяется после диагностики, при подготовке к совещанию по решению проблем и защите целевой карты.

    5.6.2. Обязательные поля (отмечены «*»): участок / узкое место; ВПП факт, %; разрыв от нормы, п.п.; Тцикл узкого места, мин; смена, мин. Далее отметьте подтверждённые обходом признаки потерь (пп. 6.2–6.16 Прил. № 5) — каждый разворачивается в ветку дерева потерь. Спойлер «Экономика потока» (такт, цена, переменная с/с, фонд времени, флажок спроса) разблокирует расчёт ΔЭЭ; без него мероприятия ранжируются по ΔВПП. Секция «Оформление плана»: ответственный и дата начала (пустые значения заменяются помеченными допущениями).

    1. Заполните секцию «Проблема» по последнему прогону диагностики.
    2. Отметьте подтверждённые обходом признаки потерь.
    3. Заполните спойлер «Экономика потока» (при наличии данных) и секцию «Оформление плана».
    4. Нажмите «Сформировать план»; проверьте сводку и топ-5 мероприятий.
    5. Кнопкой «Показать рассуждение» раскройте полную цепочку расчёта и обоснований.
    6. Скачайте план кнопками «Скачать .docx» и «Скачать .xlsx»; сохраните прогон в проект.

    5.6.4. Цепочка расчёта: проблема по правилу ФЦК (факт, где, сколько — разрыв, последствие) → дерево потерь по отмеченным признакам и 7 видам потерь → коренные причины (метод 5 почему; при необходимости — диаграмма Исикавы по 6М) → мероприятия из библиотеки инструментов бережливого производства (SMED, пока-йоке, 5С, канбан, выравнивание производства, стандартизированная работа и др.; у каждого — электронный курс «Академии производительности»). Каждое мероприятие квантифицируется: ΔВПП, Δвремени цикла, Δвыработки, Δпроизводительности труда и ΔЭЭ по МР «Оценка экономического эффекта» редакции № 4 (связка с ЭЭ-калькулятором). Сумма ΔВПП нормируется к разрыву узкого места и не превышает его. Приоритет — по Матрице приоритезации (Прил. № 8, эффект × трудоёмкость): класс A — выполнять первыми, далее B и C.

    5.6.5. Каждый факт цепочки имеет класс доказанности: «факт» (подтверждён замером), «допущение» (нормативная оценка), «нужен замер» (данных нет — указан инструмент замера: хронометраж, фотография рабочего дня, почасовой производственный анализ). Ветки «нужен замер» подтвердите до включения мероприятий в утверждаемый план.

    5.6.6. Оговорки: оценка носит расчётный характер и не является гарантированным результатом (факт подтверждается замером «после»); часть диапазонов ΔВПП — нормативные допущения из типовых диапазонов библиотеки; отмечайте только признаки, подтверждённые обходом. Итоговые решения о составе плана, сроках и ответственных принимает руководитель проекта; план подлежит обсуждению на совещании по решению проблем и утверждению в установленном порядке.

    • «Только баллы» (быстрый) — балл проставляется по каждому направлению вручную; применяется для черновой оценки;

    6. Работа с проектом: сохранение, загрузка, сравнение прогонов

    6.1. При выбранном проекте в каждой карточке инструмента отображается блок «История прогонов проекта»: таблица «№, дата, метка, итог одной строкой, автор, комментарий».

    6.2. Загрузка прогона в форму. Кнопка «→ в форму» загружает входные данные выбранного прогона обратно в форму. Это основной сценарий замера «после»: загрузите прогон «до», введите новые замеры, сохраните результат новым прогоном; исходный прогон остаётся неизменным.

    6.3. При выборе проекта последний прогон каждого инструмента подгружается в форму автоматически, если форма не редактировалась пользователем. Если в форму введены данные, автоматическая подгрузка не выполняется; отображается кнопка-подсказка «Загрузить последний прогон».

    6.4. Сравнение «до/после» предусмотрено для трёх инструментов: «Поиск узкого места», «ЭЭ-калькулятор», «Цели SMART». Отметьте ровно два прогона и нажмите «Сравнить до/после»; прогоном «до» считается более ранний по номеру. Дельта-отчёт для диагностики содержит: изменение главного узкого места и его причины (сработавшие детекторы в обоих прогонах), изменение долей ВПП в процентных пунктах, изменение производительности и мест в ранжировании. Для ЭЭ — изменения четырёх ключевых сумм. Для SMART — уточнение целей. При различии состава операций сравнение помечается «частичным»; операции с одинаковыми наименованиями сопоставляются по порядковому номеру экземпляра (#1, #2). Сравнение прогонов разных инструментов не выполняется; сервис отказывает с поясняющим сообщением.

    6.5. Типовой сквозной сценарий проекта:

    1. Создайте проект («Новый проект»: название, предприятие, пилотный поток).
    2. Этап «Открытие» → «Цели SMART»: задайте рамку ПТ и 3–5 целей; сохраните прогон.
    3. Этап «Открытие» → «Пакет ОРД» → «Подтянуть из последнего прогона SMART» → заполните реквизиты → «Сформировать пакет (docx)» → «Сохранить прогон».
    4. Этап «Диагностика» → «Поиск узкого места»: загрузите лист ПА (вкладка «Файл Excel (.xlsx)»), выполните разметку, проверьте таблицу; сохраните прогон с меткой «до».
    5. Этап «Диагностика» → «Карта потока (КПСЦ)» → «Построить карту» → «Скачать .svg».
    6. Этап «Цель и план» → «ЭЭ-калькулятор» → «Контекст диагностики проекта» → заполните секции, укажите ключевую ставку ЦБ → сохраните прогон (комментарий «плановый ЭЭ»); при необходимости выгрузите справку ФЦК.
    7. Этап «Цель и план» → «План мероприятий»: заполните секцию «Проблема» по прогону диагностики, отметьте подтверждённые признаки потерь, заполните секцию «Экономика» → «Сформировать план» → проверьте топ-5 и цепочку («Показать рассуждение») → «Скачать .docx» / «Скачать .xlsx» → сохраните прогон.
    8. Этап «Внедрение» в текущей версии не оцифрован; реализацию утверждённого плана ведите в рабочих формах предприятия.
    9. Замер «после»: история диагностики → «→ в форму» у прогона «до» → введите новые замеры → сохраните с меткой «после» → отметьте оба прогона → «Сравнить до/после». При необходимости выполните фактический расчёт ЭЭ вторым прогоном.
    10. Этап «Закрытие» → «Протокол закрытия» → «Подтянуть данные проекта» → заполните реквизиты, факты показателей, приложения → проверьте «Итого: X / 21» → «Сформировать протокол (docx)» → «Сохранить прогон».

    9. Ограничения текущей версии

    9.1. КПСЦ — только линейный поток. Карта потока создания ценности строится для последовательности операций; ветвления, параллельные линии и возвратные петли на карте не отображаются.

    9.2. Справка ФЦК — ветка «концевой серийный поток». ЭЭ-калькулятор и выгрузка справки по форме 1.4 действуют только для концевого серийного потока и только по МР-09-2022 редакции № 2. Полуфабрикатная и позаказная ветки, мультипродукт, редакция № 4 (МР-13-2025), NPV и окупаемость находятся вне контура. Для другого типа потока сервис возвращает отказ, а не приближённое значение.

    9.3. Адрес доступа может обновляться. При недоступности адреса запросите актуальный у владельца сервиса. Учётные данные являются демонстрационными и подлежат замене при промышленном запуске.

    9.4. Учебные данные обезличены. Демонстрационные наборы («ОКЗ», «НОВОХРОМ», «Оренбив» и др.) являются синтетическими и предназначены исключительно для обучения и тестирования.

    9.5. Пакетная загрузка листов ПА не предусмотрена. Вкладка Excel выполняет разметку и извлечение таблицы операций из одного файла за сеанс (кэш на сервере — один час, в памяти — до пяти книг).

    9.6. Учётные записи отсутствуют. На внешний адрес действует один общий логин; поле «автор» прогона — свободный текст (по умолчанию «РЦК»). Разграничение прав не предусмотрено: любой пользователь, имеющий доступ к сервису, видит все проекты в общей базе.

    9.7. Часть этапов не оцифрована. На этапе «Предстарт» действуют инструменты «Отбор предприятия» (оба трека очного отбора — РЦК, Приложение № 5, и ФЦК, Приложение № 4 МР-15-2026 ред.5) и «Выбор пилотного потока»; на этапе «Цель и план» действует инструмент «План мероприятий»; ранжирование потоков, форма № 4, трекер статусов плана и инструменты этапа «Внедрение» помечены «В разработке» и являются заглушками плана развития.

    9.8. Автосохранение черновика отсутствует. Обновление страницы без сохранения прогона приводит к потере введённых данных (браузер выводит предупреждение).

    9.9. Сравнение прогонов ранних редакций ограничено. Прогоны, сохранённые до редакции v1.1, не содержат перечня сработавших детекторов; в дельта-отчёте доступна только арифметика. Для полной интерпретации пересохраните прогоны заново.

    9.10. Мероприятия формируются как расчётное предложение. Инструмент «План мероприятий» подбирает мероприятия из библиотеки инструментов ФЦК и оценивает их эффект расчётным путём; часть оценок основана на нормативных допущениях (п. 5.6.6). Окончательный состав плана, сроки и ответственные определяются рабочей группой и утверждаются руководителем проекта.

    10. Порядок проведения тестирования

    10.1. Цель тестирования — независимая проверка настоящей методички и сервиса методологом, не участвовавшим в разработке: соответствие инструкций фактическому поведению интерфейса v2.2, полнота и понятность формулировок, выявление расхождений с практикой ведения проектов.

    10.2. Условия. Тестирование выполняется по адресу и учётным данным, направленным владельцем сервиса (п. 2.1.3). Допускается использование учебных проектов и демо-данных; ввод реальных данных предприятий не требуется. Ориентировочная продолжительность — 60–90 минут.

    10.3. Сценарии теста (выполняйте последовательно, фиксируя результат по каждому заданию: «выполнено / не выполнено / замечание»):

    1. Вход и навигация. Войдите по внешней ссылке. Переключитесь из режима «Простой старт» в «Полный режим». Откройте по боковому меню этапы «Диагностика» и «Помощь». Убедитесь, что на экране отображается один этап, а «Помощь» содержит методичку.
    2. Поиск узкого места по демо-данным. В карточке «Поиск узкого места» нажмите «Демо: ОКЗ (комбикорм)». Убедитесь, что появилась плашка «Главное узкое место» (операция «фасовка») и отчёт с расчётами. Проверьте валидацию: введите текст в числовую ячейку (красная подсветка) и очистите обязательную ячейку (янтарная подсветка, плашка «отчёт устарел»).
    3. Построение КПСЦ. Не изменяя данные таблицы, нажмите «Построить карту» в карточке «Карта потока (КПСЦ)». Убедитесь, что узкое место отмечено звездой, итоги (Σ времени ценности, Σ потерь, ВПП, доля ценности) отображены. Скачайте карту кнопкой «Скачать .svg» и откройте файл.
    4. Расчёт экономического эффекта. В карточке «ЭЭ-калькулятор» нажмите «Демо: НОВОХРОМ». Убедитесь, что отображены четыре итоговые величины (реальный ЭЭ, потенциальный ЭЭ, высвобождение, налоги за 3 года) и что факторная декомпозиция сходится. Ознакомьтесь с расшифровками метрик (знак «?» у полей).
    5. Выгрузка справки ФЦК. Нажмите «Скачать справку ФЦК». Убедитесь, что скачан файл .xlsm с именем «1.4 Справка_ЭЭ_…». Откройте файл в Excel и проверьте, что поля заполнены данными формы, а итоговые значения пересчитались при открытии.
    6. Работа с проектом. Создайте новый проект (название, предприятие, поток). Сохраните прогон диагностики с меткой «до». Нажмите «→ в форму» у сохранённого прогона, измените один замер, сохраните второй прогон с меткой «после». Отметьте оба прогона и нажмите «Сравнить до/после» — убедитесь, что сформирован дельта-отчёт.
    7. Протокол закрытия. Откройте «Протокол закрытия», нажмите «Подтянуть данные проекта». Проверьте, что подставленные значения соответствуют прогонам проекта. Заполните несколько направлений чек-листа «21 балл» в режиме «по требованиям» и проверьте пересчёт строки «Итого: X / 21».

    Приложение Б. Глоссарий терминов

    Пилотный поток
    Поток ключевого продукта, выбранный для реализации пилотного проекта по повышению производительности труда (МР-15-2026, п. 2): производственный процесс изготовления продукта или оказания услуги от заказа до поставки потребителю, имеющий потенциал быстрых улучшений. Предварительно определяется на стартовой встрече очного отбора и подтверждается обходом (Приложение № 3); выбирается по критериям разделов 5–6 чек-листов — им посвящён инструмент «Выбор пилотного потока».
    Отсекающий критерий
    Пункт чек-листа очного отбора с отметкой «*»: отрицательный ответ по нему отклоняет предприятие независимо от суммы баллов (п. 3.7 МР-15-2026). В треке РЦК (Прил. № 5) — пункты 1.1, 1.2, 1.4, 3, 4; в треке ФЦК (Прил. № 4) — 1.1, 1.2, 1.3, 1.5, 3.
    Скоринг-карта
    Итоговый отчёт инструментов этапа «Предстарт» в формате markdown: предприятие, дата оценки, ответы, баллы по разделам, порог, вердикт с обоснованием. Скачивается кнопкой «Скачать (.md)»; при сохранении прогона текст скоринг-карты попадает в неизменяемый снапшот проекта.
    ВПП (время протекания продукции)
    Полное время производственного цикла: суммарное время прохождения единицы продукции через весь поток, от сырья до отгрузки. Поле «ВПП итого, сек» инструмента «Поиск узкого места» считается автоматически как сумма ВПП операций.
    Тц (время цикла)
    Время выполнения одной операции потока; в таблице операций задаётся в минутах (поле «Тц, мин»). Используется детектором узкого места «время цикла».
    Время такта
    Интервал времени, задающий темп выпуска, ориентированный на спрос клиента. Такт = доступное время ÷ спрос; поле «Такт, мин» заполняется автоматически, когда заданы спрос и доступное время.
    Узкое место
    Операция, ограничивающая темп всего потока. Определяется по четырём независимым детекторам: время цикла (Тц), темп потока (минимальная производительность), доля во времени производственного цикла (ВПП; первый эшелон ≥ 25 %, второй ≥ 10 %), переделка (возврат, %). Главным узким местом признаётся кандидат, подтверждённый не менее чем двумя детекторами.
    Поток создания ценности
    Последовательность операций, через которые проходит продукт от сырья до клиента; пилотный поток задаётся в карточке проекта и проверяется контролем контекста при подстановке данных между инструментами.
    КПСЦ (карта потока создания ценности)
    Карта потока создания ценности, строится по данным таблицы операций инструмента «Поиск узкого места» для линейного потока; главное узкое место отмечается на карте знаком «звезда».
    VA / NVA
    Время создания ценности (VA) и время без создания ценности (NVA). На линии времени карты КПСЦ нижние отрезки — VA = Тц операции; верхние — NVA = ВПП − Тц по блоку (ожидание).
    Доля ценности
    Отношение времени ценности к ВПП, в процентах; выводится в итогах карты КПСЦ (ΣТц / ВПП).
    ЭЭ реальный
    Экономический эффект проекта, руб/год, рассчитанный по модели ФЦК (МР-09-2022, редакция № 2) для реализованного объёма; выводится в плашке итогов ЭЭ-калькулятора с факторной декомпозицией.
    ЭЭ потенциальный
    Резерв мощности и потенциальная аренда, рассчитанные по модели ФЦК (МР-09-2022, редакция № 2); выводится в плашке итогов ЭЭ-калькулятора рядом с реальным ЭЭ.
    Высвобождение
    Высвобождение денежных средств — разовый эффект из запасов, рассчитываемый в ЭЭ-калькуляторе с учётом ключевой ставки ЦБ.
    ОРД (организационно-распорядительная документация)
    Пакет документов этапа «Открытие»: приказ о назначении ответственных за реализацию мероприятий (приложение № 2 МУ-65) и карточка проекта; формируется одним файлом Word.
    SMART
    Способ постановки целей проекта (МУ-65, п. 4.1.5): разворот целей S/M/A/R/T с методикой расчёта каждого показателя по МУ-66-2024 и проверками измеримости, порога достижимости 30 %, наличия обязательного показателя и соответствия рамке ПТ.
    Прогон
    Сохранённый в проекте расчёт одного инструмента: входные данные, отчёт, ключевые итоги, автор, дата, комментарий. Прогон неизменяем: редактирование и удаление не предусмотрены.
    Проект
    Запись в базе сервиса: название, предприятие, пилотный поток создания ценности. Создаётся кнопкой «Новый проект»; обязательным является только название.
    МУ-65-2024
    Методические указания «Реализация проектов по улучшениям» ФЦК — маршрут проекта по улучшению от открытия до протокола закрытия, который оцифровывает сервис.
    МР-08-2026
    Методические рекомендации «Реализация программы ППТ на предприятии с поддержкой РЦК»: главный маршрут пилотного проекта с РЦК (2 фазы, окно 19–28 недель); приложение № 6 — протокол выполнения мероприятий.
    МР-09-2022
    Методические рекомендации «Оценка экономического эффекта от реализации мероприятий», редакция № 2 — официальная модель расчёта ЭЭ, применяемая ЭЭ-калькулятором (условный год, цены «до», суммы без НДС, концевой серийный поток).
    Доступное время
    Фонд времени периода, в течение которого поток может выпускать продукцию (поле «Доступное время, мин» инструмента «Поиск узкого места»); источник данных — режим работы. Вместе со спросом определяет такт.
    Спрос
    Потребность периода в продукции потока (поле «Спрос, шт/период»); источник данных — план продаж или заказы. Спрос и доступное время разблокируют дополнительные блоки отчёта диагностики.
    Производительность
    Выход операции в единицу времени (поле «Произв., т/ч» таблицы операций). Используется детектором «темп потока»: узким местом признаётся операция с минимальной производительностью.
    Возврат (переделка, брак)
    Доля продукции, возвращаемой на переделку, в процентах (поле «Возврат, %» таблицы операций). Используется детектором «переделка»; в ЭЭ-калькуляторе отдельно учитывается неисправимый брак до/после, %.
    Запас перед операцией (треугольник I)
    Запас, накопленный перед операцией потока; на карте потока создания ценности по «Learning to See» изображается треугольником запасов. В служебном JSON спецификации № 1 передаётся полем «запас_перед_шт»; при отсутствии данных о запасах они включаются в перечень «домерить».
    Инфопоток
    Поток информации, управляющий потоком создания ценности (заказы, планирование, задания операциям). По урокам корпуса разборов узкое место может находиться в инфопотоке; в детекторах ядра v0.4 инфопоток учтён как план развития.
    Планирование (блок КПСЦ)
    Блок карты потока создания ценности, от которого информационные потоки идут к поставщику и операциям; элемент классической схемы «Learning to See» (МУ-66-2024) наряду с процесс-боксами и треугольниками запасов.
    Поставщик / клиент (блоки КПСЦ)
    Граничные блоки карты потока создания ценности: поставщик — начало потока (сырьё), клиент — его завершение (отгрузка). В карточке проекта клиенты процесса фиксируются в блоке «Вовлечённые лица и рамки» (источник — карта процесса, стартовое совещание).
    Пробел данных
    Отсутствующее значение, необходимое для расчёта. Пустое поле — отсутствие данных, а не ошибка: сервис рассчитывает показатели, для которых данных достаточно, а недостающие перечисляет в блоке «домерить»; подстановка нулевых значений не выполняется.
    Статус «с пробелами»
    Пометка итогов расчёта: при наличии пробелов данных отчёт сопровождается строкой статуса и перечнем «домерить», а краткий итог в истории прогонов отображается с пометкой «(с пробелами)».
    Детектор «время цикла»
    Один из четырёх независимых детекторов узкого места: срабатывает по времени цикла операции (Тц).
    Детектор «темп потока»
    Один из четырёх независимых детекторов узкого места: срабатывает по минимальной производительности операции в потоке.
    Детектор «доля в ВПП»
    Один из четырёх независимых детекторов узкого места: срабатывает по доле операции во времени производственного цикла; пороги: первый эшелон ≥ 25 %, второй ≥ 10 % ВПП.
    Детектор «переделка»
    Один из четырёх независимых детекторов узкого места: срабатывает по доле возврата (переделки) продукции на операции, %.
    Главное узкое место
    Кандидат в узкие места, подтверждённый не менее чем двумя независимыми детекторами; выводится в плашке «Главное узкое место» с масштабом в часах и доле ВПП и отмечается на карте КПСЦ знаком «звезда». При подтверждении одним детектором отчёт содержит указание «слабое подтверждение — домерить».
    Второй эшелон
    Вторая ступень ранжирования узких мест по детектору «доля в ВПП»: операции с долей во времени производственного цикла ≥ 10 % (первый эшелон — ≥ 25 %).
    Кросс-детектор
    Принцип кросс-подтверждения узкого места: кандидат признаётся главным узким местом, когда его указывают не менее двух независимых детекторов одновременно.
    Контекст диагностики
    Пара «предприятие · поток» проекта, подставляемая в ЭЭ-калькулятор кнопкой «Контекст диагностики проекта» вместе с подсказкой о главном узком месте и производительности операций по последнему прогону диагностики. См. также «Контекст» (п. 4.4 методички).
    Метка «до» / «после»
    Признак, присваиваемый прогону при сохранении: «до» — замер базовой линии (плановый расчёт при защите целевой карты), «после» — замер после внедрения мероприятий (фактический расчёт при закрытии). Метки используются при сравнении прогонов и при подстановке данных.
    Сравнение прогонов («до/после»)
    Дельта-отчёт по двум отмеченным прогонам одного инструмента («Поиск узкого места», «ЭЭ-калькулятор», «Цели SMART»); прогоном «до» считается более ранний по номеру. Для диагностики содержит изменение главного узкого места, долей ВПП и производительности; при различии состава операций помечается «частичным».
    Immutable-прогон (неизменяемый прогон)
    Свойство прогона: редактирование и удаление не предусмотрены. При ошибочном вводе создаётся новый прогон с поясняющим комментарием; история проекта ведётся по принципу лабораторного журнала. При сохранении сервер повторно выполняет расчёт по входным данным — подмена итогов исключена.
    Линейный поток
    Последовательность операций без ветвлений, параллельных линий и возвратных петель; единственный вид потока, для которого в текущей версии строится карта КПСЦ.
    Условный год
    Рамка модели ЭЭ (МР-09-2022, редакция № 2): расчёт ведётся в горизонте условного года, в ценах «до», суммами без НДС.
    Концевой серийный поток
    Контур применимости ЭЭ-калькулятора и справки ФЦК по форме 1.4: ветка «концевой серийный поток» модели МР-09-2022 редакции № 2. Полуфабрикатная и позаказная ветки, мультипродукт, редакция № 4 (МР-13-2025), NPV и окупаемость находятся вне контура; для другого типа потока сервис возвращает отказ, а не приближённое значение.
    Факторная декомпозиция
    Раскладка реального ЭЭ по факторам в отчёте ЭЭ-калькулятора с контрольной сверкой: сумма факторов должна равняться реальному ЭЭ; расхождение сопровождается предупреждением.
    Резерв мощности
    Составляющая потенциального ЭЭ наряду с потенциальной арендой; рассчитывается по модели ФЦК (МР-09-2022, редакция № 2) и выводится в плашке итогов ЭЭ-калькулятора.
    Ключевая ставка ЦБ
    Константа расчёта ЭЭ, принимаемая по сайту ЦБ (cbr.ru) на дату расчёта; участвует в эффекте высвобождения денежных средств из запасов.
    НДС (в модели ЭЭ)
    Константа расчёта (по умолчанию 20 %). Модель МР-09-2022 редакции № 2 оперирует суммами без НДС: цена единицы и переменная себестоимость вводятся без НДС.
    Высвобождение из запасов
    Разовый эффект высвобождения денежных средств из запасов (сырьё и материалы, готовая продукция, НЗП до/после, руб); рассчитывается в ЭЭ-калькуляторе с учётом ключевой ставки ЦБ.
    Рамка ПТ
    Рамка производительности труда для целей проекта: федеральная (+5 %/год, 15 % к третьему году) или региональная (+10/15/30 %). Выбирается в инструменте «Цели SMART»; целевой уровень показателей задаётся по рамке, соответствие проверяется валидатором.
    Чек-лист «21 балл»
    Приложение № 2 протокола закрытия: 14 направлений развития производственной системы с оценкой 0–3 по каждому; порог зачёта — 21 балл. Режимы ввода: «Только баллы» (быстрый) и «По требованиям» (официальная форма с автоматическим расчётом баллов по методике уровней).
    Акт начала мероприятий
    Документ предстартового этапа (МР-08-2026, 0.1/0.3): подписывается ГД и РЦК и является точкой отсчёта всех сроков проекта.
    Стартовое совещание
    Мероприятие этапа «Открытие» (МР-08, 3.2), проводится по типовой повестке и презентации (МР-25-2025) с анкетой по итогам; его материалы являются источником рисков и рамок для карточки проекта.
    Целевая карта
    Карта целевого состояния потока с пересчётом показателей (ВПП, выработка, запасы) — выход этапа «Цель и план» (МР-08, 2.3); плановый расчёт ЭЭ выполняется при её защите и сохраняется прогоном с меткой «до».
    План-график
    План мероприятий проекта, утверждаемый ГД по итогам защиты и направляемый в РЦК (МР-08, 2.5–2.6); источник ключевых событий для пакета ОРД. По МР-08 окно реализации — 19–28 недель; этап «Внедрение» в текущей версии не оцифрован, план-график ведётся в рабочих формах предприятия.
    Дерево потерь
    Разложение симптома (проблемы узкого места) на ветки по 15 признакам потерь (пп. 6.2–6.16 Прил. № 5 МР-15-2026) и 7 видам потерь (Приложение № 1 «Виды потерь») в инструменте «План мероприятий». Каждая ветка квантифицируется; при отсутствии данных получает метку «нужен замер».
    5 почему
    Метод поиска коренной причины: последовательное повторение вопроса «почему» до причины, на которую можно воздействовать мероприятием. В инструменте «План мероприятий» каждый шаг цепочки снабжается классом доказанности.
    Диаграмма Исикавы (6М)
    Диаграмма причинно-следственных связей («рыбья кость») по шести группам причин: человек, машина, материал, метод, измерение, среда. Применяется при поиске коренных причин наряду с методом 5 почему.
    Класс доказанности
    Метка каждого факта цепочки расчёта в инструменте «План мероприятий»: «факт» — подтверждён замером или прогоном диагностики; «допущение» — нормативная оценка; «нужен замер» — данных нет, указан рекомендуемый инструмент замера (хронометраж, фотография рабочего дня, почасовой производственный анализ). Раскрывается кнопкой «Показать рассуждение».
    SMED (быстрая переналадка)
    Инструмент бережливого производства по сокращению времени переналадки оборудования: перевод внутренних операций во внешние и упорядочение оставшихся. Входит в библиотеку инструментов ФЦК; обучение — курс «Академии производительности» «Быстрая переналадка (SMED)».
    Пока-йоке (защита от ошибок)
    Инструмент бережливого производства: приёмы и устройства, исключающие появление дефекта или делающие ошибку невозможной/сразу видимой. Входит в библиотеку инструментов ФЦК; обучение — курс «Защита от ошибок (пока-йоке)».
    Канбан
    Система управления запасами и вытягивающего потока сигнальными картами: пополнение выполняется только по фактическому расходу. Входит в библиотеку инструментов ФЦК; при отсутствии данных для расчёта канбана ветка получает метку «нужен замер».
    Хейдзунка (выравнивание производства)
    Инструмент выравнивания производственной программы по объёму и номенклатуре для сглаживания загрузки потока. Входит в библиотеку инструментов ФЦК; обучение — курс «Выравнивание производства (хейдзунка)».
    Стандартизированная работа
    Инструмент бережливого производства: зафиксированная лучшая известная последовательность операций с нормативами времени и заделов; основа для обучения и дальнейших улучшений. Входит в библиотеку инструментов ФЦК.
    Матрица приоритезации
    Матрица «эффект × трудоёмкость» (Приложение № 8 «Матрица приоритезации проблем»): ячейке соответствует класс приоритета мероприятия — A (выполнять первыми), B или C. Пороги эффекта: высокое влияние > 5 %, низкое < 2 %; сроки предлагаются по классу трудоёмкости.
    Библиотека инструментов ФЦК
    Встроенный справочник инструментов бережливого производства (SMED, пока-йоке, 5С, канбан, выравнивание производства, стандартизированная работа и др.), из которого инструмент «План мероприятий» подбирает мероприятия по типу причины; у каждого инструмента указан типовой диапазон ΔВПП и электронный курс «Академии производительности».
