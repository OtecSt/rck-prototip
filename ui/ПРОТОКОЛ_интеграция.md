# ПРОТОКОЛ_интеграция — инструкция интегратору (волна 2А)

> Ядро: `Прототип/protokol_zakrytiya.py` — генератор «Протокола выполнения
> мероприятий по Соглашению» (протокол закрытия, этап 5 спины МУ-65).
> CLI: `python3 protokol_zakrytiya.py данные.json [выход.docx]` → stdout JSON
> `{итого_баллов, порог, порог_пройден, незаполненных_полей, путь}`.
> Точка входа для сервера: `сгенерировать(данные: dict, путь_выход: str) -> dict`.

## 1. Карточка в UI (этап 5)

Новая карточка **«Протокол закрытия»** на этапе 5 (после карточек этапа 3 «ЭЭ-калькулятор»). Назначение: собрать реквизиты + приложения и скачать docx.

Поля формы (все опциональны — ядро работает в режиме частичных данных, «___» + список «домерить» в конце docx):

- Реквизиты: `предприятие`, `рцк`, `соглашение.номер`, `соглашение.дата`,
  `период.с`, `период.по`, `место_подписания`, `дата_протокола`,
  `поток_ключевого_продукта`.
- Подписанты: `подписанты.предприятие.{должность,фио}`, `подписанты.рцк.{должность,фио}`.
- Таблица показателей (динамические строки): `показатели[] {показатель, ед_изм, до, цель, факт}`.
- Проекты и цели: `проекты_и_цели[] {проект, цели{ВПП,Запасы,Выработка,"Дополнительный показатель"}}`.
- Цели ПТ: `цели_пт {к_базовому_году_пкт, к_3_году_пкт}` — **дефолт 5 и 15** (федеральная рамка, вшита в форму).
- ЭЭ: `ээ_руб_год` (число) — **автоподтяжка из прогонов** (см. §3).
- Лучшие практики: `лучшие_практики[]` (строки).
- Прил. № 1: `мероприятия_результаты { "1.1": "Выполнено", ... }` — дефолт всех 27 мероприятий «Выполнено»; селектор Выполнено/Не выполнено/не заполнять. Полный список мероприятий — в `protokol_zakrytiya.СКЕЛЕТ["meropriyatiya"]` (фронт может импортировать ключи через API, см. §2).
- Прил. № 2 (чек-лист «21 балл»): `чеклист.баллы {"1": 0..3, ..., "14": 0..3}` — 14 селекторов 0–3 по направлениям (названия — `СКЕЛЕТ["napravleniya"]`). Итог и порог считает ядро; фронт может дублировать живую сумму и индикатор «порог 21 пройден/не пройден».

## 2. API-эндпоинты

### `POST /api/protokol` → docx на скачивание
Запрос: `{"id_proekta": N, "данные": { ...вход-JSON ядра... }}` (id проекта нужен только для автоподтяжки, см. §3).
Сервер: подтягивает ЭЭ/УМ из прогонов проекта → `сгенерировать(данные, tmp)` →
`send_file(tmp, as_attachment=True, download_name="Протокол закрытия.docx")`.
Ответ при ошибках валидации — `{"ok": false, "errors": [...]}` как в контракте.

### `GET /api/protokol/skelet` (рекомендуется)
Отдаёт `{"napravleniya": [...14...], "meropriyatiya": [[номер,название,раздел], ...]}`
из `protokol_zakrytiya.СКЕЛЕТ` — чтобы фронт строил селекторы без дублирования текстов.

## 3. Автоподтяжка из прогонов (КОНТРАКТ_данных.md, §3)

По `id_proekta` сервер читает `progony` проекта и заполняет поля, не заданные пользователем:

- `ээ_руб_год` ← последний прогон `инструмент='ee'`: `итоги_json.ээ` (руб/год, `null` → не подставлять). При наличии пары «до/после» брать прогон с меткой `'после'`, иначе последний по id.
- `поток_ключевого_продукта` ← `proekty.поток` (или `итоги_json.поток` прогона `ee`).
- `предприятие` ← `proekty.предприятие` (или `итоги_json.предприятие` прогона `ee`).
- Подсказка для показателей (не автозаполнение): главное УМ ← последний прогон `uzkie_mesta` (`итоги_json.главное_ум`) — показывать в форме подсказкой «узкое место: …».

Правило: **явное значение из формы всегда перекрывает подтяжку.**

## 4. Сохранение в историю

Прогон протокола — тоже прогон (`POST /api/progony`), но у протокола нет «до/после»:

- Реестр: добавить в `ИНСТРУМЕНТЫ` `{"protokol": {"этап": 5, "название": "Протокол закрытия"}}`.
- `вход_json` — полный вход-JSON ядра.
- `итоги_json`: `{"итого_баллов": 22, "порог": 21, "порог_пройден": true, "незаполненных_полей": N, "ээ_руб_год": X|null}`.
- `отчёт_md` — короткая сводка: реквизиты, итог баллов, порог, список «домерить».
- Ветка `sravnit()` для `protokol` — **не нужна** (сравнение прогонов протокола бессмысленно); в UI скрыть чекбоксы сравнения для этого инструмента.

## 5. Шапка истории (строка прогона)

Формат итоговой колонки: `«Протокол: 22/21 балл — порог пройден»` /
`«…18/21 — порог НЕ пройден»` / `«…неполный (N полей домерить)»` + дата + автор.
Кнопка «скачать docx» в строке прогона — ре-генерация из сохранённого `вход_json` (документ immutable, как и прогон: повторная генерация из того же входа даёт тот же документ).

## 6. Ограничения (из проверки v01)

- Чек-лист вводится баллами по 14 направлениям (0–3), не по 87 требованиям.
- Формулировка нацпроекта в шапке — редакция 2022 г.; для проектов 2025+ («Эффективная и конкурентная экономика») правится вручную в docx (см. `результаты/проверка_протокола_v01.md`, §5).
