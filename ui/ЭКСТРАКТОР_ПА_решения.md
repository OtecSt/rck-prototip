## Этап А. Разведка: как устроены реальные ПА

### А.1. ОКЗ (комбикорм) — источник эталона

Файл: `проеткы/ОКЗ/Доки ОКЗ/Картирование/1. Текущее состояние/Текущая карта  ОКЗ.xlsx`
(81 КБ, 1 лист «Карта текущего состояния», 46×33).

Структура — **транспонированная матрица КПСЦ**: операции лежат по столбцам, показатели — по строкам:

| Строка | Содержимое |
|---|---|
| 15 | подоперации (C15…AF15: «Дозирование растительного сырья» … «Перемещение погрузчика…») |
| 20 | блоки процессов (C20 «Процесс дозирования», K20 «Процесс грануляции», X20 «Процесс фасовки…», AA20 «Процесс отгрузки…», AG20 «ИТОГО:») — **объединённые ячейки на ширину блока** |
| 21 | ВПП, сек (C=8400, K=13200, X=32400, AA…AF=6000…5250, AG=83765) — тоже объединены по блокам |
| 22 | Т цикла, **секунды** (7.2 / 11.3 / 11.7 / 12 / 10.4 / 5.14 / 6.9 / 3.8 / 3.6 / 1.6 / 4.5) |
| 23 | Персонал, чел. (по точкам, итого 10) |
| 24 | Партия, т (35, объединённая на блок) |
| 25 | Производительность, т/час (C=15, K=9.5455, X=3.9) |
| 29–46 | список проблем текстом (в т.ч. строка 33: «около 30% продукции повторно проходит этапы грануляции») |

Возврат 30 % по грануляции существует **только как текст в списке проблем** — структурно не извлекается.

Другие файлы ОКЗ: `Шаблон ПА.xlsx` (почасовой бланк план/факт/простои), `Пример ОКЗ.xlsx` (ДЦ/маржа — не ПА).

### А.2. Ещё 3 проекта

- **Оренбив** (мясопереработка): `Производственный анализ. Фасовка 07.2025.xlsx`, 7 листов. Лист1 — сводная по датам (суммы, доли) + вторая таблица по номенклатуре (части туши × часы) — **несколько таблиц на одном листе**, без заголовков колонок в машинном виде.
- **Гайфа** (птицефабрика): `Пример листа производственного анализа.xlsx` — тот же почасовой бланк, что у ОКЗ: «Время / План шт. / Факт / Отклонение / Время простоя / Причина». Два варианта (гофрокороб, упаковка яиц) + «пример ПА в excel».
- **Технопром** (металлообработка): `Производственный анализ.xlsx`, 1 лист 19×8 — план/факт по деталям + причины простоя, шапка из 6 строк, время такта «-».

### А.3. Вывод разведки

1. **Типового шаблона ПА нет.** Есть семейство «почасовой бланк ППА» (ОКЗ/Гайфа — про план/факт и простои, там нет Тц/ВПП), а данные для узких мест живут в **картах КПСЦ**, структура которых уникальна (ОКЗ — транспонированная с merged-блоками).
2. Ориентации две: «операция = строка» и «операция = столбец». Обе встречаются.
3. На одном листе бывает несколько таблиц (Оренбив) — нужен выбор диапазона (старт/конец).
4. Объединённые ячейки — семантически двусмысленны: метрика блока, размазанная на подоперации. Авторазвёртка **ломает данные** (проверено опытом: ВПП блока дозирования размножился на 8 подопераций).
5. Единицы Тц плавают (секунды у ОКЗ — эталон вручную делил на 60).
6. LLM в продуктовом рантайме нет, а эвристики на таком разнообразии = молча неправильные числа.

**Поэтому: ассистент разметки.** Человек видит превью с координатами и 5 кликами размечает; машина извлекает детерминированно; разметка запоминается.

## Этап Б. Что сделано

- Вкладка «Файл Excel (.xlsx)» — четвёртая, рядом с Таблица/TSV/JSON.
- `POST /api/excel_preview` (multipart): лимит 20 МБ (Flask 413 + своя проверка), отказ .xls с честным текстом (xlrd в окружении нет), битый файл → понятная ошибка. Ответ: листы × превью 30 строк × 20 колонок с координатами A1; объединённые ячейки подсвечены и показаны значением главной (только визуально).
- Кеш книг в памяти по токену (TTL 1 ч, ≤5 книг), повторная загрузка не нужна; протухший токен → «загрузите заново».
- Разметка в UI: ориентация (строки/столбцы), поля имя/Тц/производительность/ВПП/возврат (буквы колонок или № строк), старт и **конец** диапазона, единица Тц (мин/сек → автоделение на 60).
- `POST /api/excel_extract`: детерминированное извлечение → `операции[]` → заполняет основную таблицу → обычный живой пересчёт `/api/raschet` (не тронут).
- Числа: `1 234,5`, `30%`, неразрывные пробелы, прочерки; мусор → предупреждение «не число», дальше обычная подсветка в таблице.
- localStorage по ключу `файл::лист` — кнопка «Применить сохранённую разметку».
- Заглушка «Экстрактор данных из листов ПА (скоро)» убрана — инструмент реализован.

## Проверка: что извлеклось, что нет

### ОКЗ 1:1 с эталоном `данные_окз_слепой.json`

Разметка: лист «Карта текущего состояния», ориентация «в столбцах», имя=строка 15, ВПП=21, Тц=22 (в секундах), производительность=25, диапазон 3–32.

- **Извлеклось автоматом**: 11 операций — все Тц (с точным совпадением после /60: 0.12, 0.1883, 0.195, 0.2, 0.1733, 0.0857, 0.115, 0.0633, 0.06, 0.0267, 0.075), все ВПП (8400/13200/32400/6000/8050/4410/4200/1855/5250), производительности (15 / 9.5455 / 3.9). Подоперации без чисел (19 шт.) пропущены с предупреждениями.
- **Расчёт**: главное УМ = фасовка, **3.9 т/ч, ВПП 32400 сек = 38,7 %**, подтверждено 2+ детекторами; эшелон 2 = грануляция (имя «Накопительный бункер пресов» — первая ячейка блока), эшелон 2 = дозирование. **Ранжирование 1:1 с эталоном по существу и цифрам.**
- **Не извлеклось (честно)**:
  1. `возврат_пкт = 30` по грануляции — в файле это текст в списке проблем (строка 33), не число в таблице. Пользователь вписывает в таблицу рукой (1 ячейка).
  2. Собирательные имена блоков («Процесс грануляции (накопительный бункер → … → взвешивание)») — эталон составил их вручную из строк 20 и 15; ассистент берёт одну строку имён. На ранжирование не влияет.
  3. Мета-поля (ВПП итого 83765, персонал 10) — сидят в AG21/AG23, но колонка AG («ИТОГО:») исключена разметкой диапазона; проще вписать в поля проекта (2 значения), они и в эталоне заданы вручную.
  4. Имена с `\n` из ячеек («Фасовка \nв мешок 30 кг.») — косметика, видно в таблице, правится на месте.

### Оренбив (без эталона)

7 листов прочитаны; по разметке (Лист1, строки 20–38, имя=A, Тц=E) извлечено 19 наименований разделки с временами — осмысленный результат, расчёт проходит, главное УМ не выносится (мало детекторов — корректно для одного показателя).

## Ограничения (зафиксированные)

1. Объединённые ячейки при извлечении **не разворачиваются** (значение только из главной ячейки) — иначе метрика блока размножается и ломает ранжирование (проверено). Побочка: если нужное число — именно объединённая шапка, главная ячейка всё равно отдаёт значение, так что рабочий путь есть.
2. Сущности без единого числа пропускаются с предупреждением (подоперации, строки-комментарии). Пользователь видит список пропущенного.
3. .xls не поддерживается (нет xlrd) — честная ошибка с инструкцией.
4. Стоп-граница извлечения: 500 строк/столбцов от старта.
5. Кеш в памяти — перезапуск сервера = загрузить файл заново.
6. Семантика («эта строка — возврат %») остаётся на человеке: инструмент гарантирует детерминизм, а не понимание документа.
