# UX-аудит интерфейса «Агент-цех» (v2.0) — бриф редизайна

**Аудитор:** UX_Аудитор · **Дата:** 2026 · **Объект:** `ui/templates/index.html` + `ui/static/style.css` + скриншоты `skrin1.png`, `skrin2.png`
**Аудитория:** инженеры РЦК 35–55 лет, не IT-пользователи; сценарий «зашёл решить задачу — ушёл».

---

## 1. Диагноз: конкретные проблемы этого UI

### Навигация и структура

- **N1. Длинный вертикальный скролл как единственный способ перемещения.** Все 6 этапов и 6 живых инструментов лежат в одном потоке (`index.html`, `<ol class="stages">`, строки 60–840+; файл 3174 строки). Между «Диагностикой» (этап 2) и «ЭЭ-калькулятором» (этап 3) — сотни пикселей скролла; раскрытый `<details>` этапа увеличивает страницу ещё сильнее. Возврат «наверх» к другому этапу требует прокрутки всей карты/отчёта.
- **N2. Нет оглавления/карты «где я и что дальше».** Нумерованная линейка этапов (`stage-num`) — декоративна: только текущий этап подсвечен (`.stage.current`, css 118–123), но нет кликабельной навигации, индикаторов заполненности этапа и «хлебных крошек».
- **N3. Переключатель режимов «Простой старт / Полный режим» — скрытая бифуркация.** В простом режиме CSS-правила `display:none` вырезают проекты, историю и вкладки ввода (css 806–811). Пользователь, начавший в простом режиме, не знает, что история существует; в полном режиме простая «одна задача» недоступна. Это классическая проблема двух приложений в одном.
- **N4. Проект выбирается в шапке, но контекст «размазан».** Подсказка «выберите проект в шапке» (строка 528) — хорошо, но сама шапка при скролле уезжает: на этапе 3 пользователь уже не видит, какой проект активен.

### Плотность и формы

- **F1. ЭЭ-калькулятор — 35+ полей подряд** (строки 519–638): 8 секций по 3–9 полей в `meta-grid` без иерархии приоритетов. Скриншот `skrin2.png` показывает: даже раскрытая карточка не влезает в экран, обязательные (*) и необязательные поля визуально равны. Для не-IT пользователя это «стена полей».
- **F2. Таблица операций 11 строк × 5 колонок** (`ops-table`, строки 322–338) — приемлема по ширине, но: нет sticky-заголовка, нет нумерации строк, прозрачные рамки инпутов (`border: 1px solid transparent`, css 278–289) скрывают редактируемость до hover; пустая таблица выглядит как пустое место без подсказки, с чего начать.
- **F3. Четыре вкладки ввода** («Таблица / Вставить из Excel / Файл JSON / Файл Excel .xlsx», строки 313–320) — избыточная когнитивная нагрузка: «Файл JSON» — служебный путь, которому не место рядом с пользовательскими.

### Находимость кнопок и статусы

- **B1. Кнопка «Построить карту»** у КПСЦ `disabled` до валидных данных (строка 467) — правильно, но причина блокировки только мелким hint'ом справа; на скриншоте `skrin1.png` кнопки «Построить карту» / «Скачать .svg» разной визуальной весомости стоят рядом и конкурируют.
- **B2. Статусы — текстовые строки без иконок** (`.status-line`, css 320–328). «С ПРОБЕЛАМИ» на карте (skrin1) — красный текст поверх другого красного текста; итоги под картой дублируют data-box карты. Цвет — единственный канал (проблема доступности).
- **B3. Обратная связь после расчёта — «отчёт появился где-то ниже».** Результат живого пересчёта (`.result-zone`) рендерится под формой; при длинной форме (ЭЭ) пользователь меняет поле и не видит, что отчёт обновился, — нет ни скролл-якоря, ни тоста «пересчитано».

### Пустые состояния и подсказки

- **E1. Empty states почти отсутствуют.** История прогонов — блок `hidden` до первых данных; пустая таблица операций — просто пусто; нет ни одного экрана «начните отсюда / вот что будет результатом».
- **E2. Справки «?» есть только у 5 живых инструментов**, и это единый монолитный абзац на 4–8 строк (например, строки 285–292). Нет подсказок на уровне полей (что такое «Тнеобх.такт»?), нет ссылки на методичку.
- **E3. Stub-карточки «скоро»** (6 штук, напр. строки 70–73) занимают место и шумят, пользы не несут.

## 2. Рекомендации по приоритету

### P0 — критично для целевой аудитории

**P0-1. Боковое меню с иконками и подсказками (запрос пользователя).**
- *Что меняем:* слева фиксированная колонка 220–240px: 6 этапов с иконкой, номером и статусом (пусто / в работе / есть прогон), ниже — живые инструменты текущего этапа, внизу — «Помощь / Методичка». Клик = переключение видимого этапа (один этап на экране, как вкладки), а не якорный скролл. Ширину контента 960px сохраняем: `main` сдвигается, `max-width` страницы растёт до ~1200px.
- *Зачем:* устраняет N1–N2; боковая навигация — стандарт де-факто для многоэтапных внутренних инструментов, она всегда видна при скролле и масштабируется лучше верхних вкладок при 6+ пунктах ([Eleken, Tabs UX](https://www.eleken.co/blog-posts/tabs-ux) — «не натягивайте вкладки там, где лучше sidebar или progressive disclosure»).
- *Опора:* только CSS + небольшой JS-класс-переключатель; DOM-структуру `<li class="stage">` и все `id` не трогаем — этапы остаются теми же `<details>`, просто открывается всегда один.

**P0-2. Иерархия ЭЭ-калькулятора: обязательное вперёд, остальное под спойлер.**
- *Что меняем:* секция «Объём и цены» (9 обязательных полей) — всегда раскрыта; «Дельты норм», «Дельты постоянных», «Брак/аренда», «Запасы», «Константы» — сворачиваемые `<details>` с бейджем «заполнено n полей». Обязательные (*) визуально усилить (терракотовая звёздочка уже есть — добавить подчёркивание лейбла).
- *Зачем:* F1 — стена из 35 полей; progressive disclosure — базовый приём снижения нагрузки ([IxDF, Progressive Disclosure](https://ixdf.org/literature/topics/progressive-disclosure)).
- *Опора:* id инпутов не меняются — JS-мосты не страдают.

**P0-3. Обратная связь после расчёта.**
- *Что меняем:* после живого пересчёта — ненавязчивый тост «Отчёт обновлён · главное УМ: сборка» + плавающая кнопка «↓ к отчёту», когда результат вне вьюпорта. Статус-строки снабдить иконками ✓ / ⚠ / ✕, текст «С ПРОБЕЛАМИ» не дублировать красным поверх карты (bug с наложением виден на skrin1 — шапка карты и статус наезжают друг на друга).
- *Зачем:* B2–B3; цвет не должен быть единственным каналом статуса (WCAG).

### P1 — заметно улучшает ежедневную работу

**P1-1. Встроенная методичка — панель помощи.**
- *Что меняем:* пункт «Методичка» в боковом меню: страница с оглавлением МУ-65/МУ-66/МР-09 по этапам, поиском и ссылками «открыть из инструмента». Каждая справка «?» получает внизу ссылку «Подробнее в методичке → раздел».
- *Зачем:* E2; пользователи работают по бумажным методичкам — соответствие «экран ↔ документ» снимает главный страх «а правильно ли я считаю».

**P1-2. Подсказки на уровне полей.**
- *Что меняем:* маленькие «?» у неочевидных полей (Тнеобх.такт, ВПП, рамка ПТ, ключевая ставка ЦБ) с однострочным тултипом; монолитные справки инструментов разбить на 2–3 абзаца с заголовками.
- *Опора:* контекстные подсказки по месту работают лучше линейных туров для инструментальных сценариев ([User onboarding handbook 2026](https://usertourkit.com/blog/user-onboarding-handbook)).

**P1-3. Empty states везде.**
- *Что меняем:* пустая таблица операций → плейсхолдер-строка «дозирование · 0,12 · …» + кнопки «Демо» и «Вставить из Excel» прямо в пустом теле таблицы; пустая история → «Прогонов пока нет — сохраните первый после расчёта»; пустой проект в шапке → приглашение создать.
- *Зачем:* E1; пустые состояния — это onboarding-поверхность, а не тупик ([UXPin, Empty States](https://www.uxpin.com/studio/blog/ux-best-practices-designing-the-overlooked-empty-states/)).

**P1-4. Таблица операций: плотность и редактируемость.**
- *Что меняем:* видимые границы инпутов по умолчанию (убрать `transparent`), нумерация строк, sticky `<thead>` при >10 строк, авто-добавление строки при заполнении последней, клавиша Enter = следующая ячейка вниз. Заголовки колонок с единицами — в тултип, чтобы сузить шапку.
- *Зачем:* F2 — скрытая редактируемость вводит в заблуждение «это отчёт, а не форма».

**P1-5. Убрать шум.**
- *Что меняем:* stub-карточки «скоро» свернуть в одну строку «В разработке: …» в конце этапа; вкладку «Файл JSON» убрать в ссылку «служебный импорт» внизу панели ввода; простой и полный режим слить: простой экран = тот же этап «Диагностика», но с выключенными проектами/историей, и боковое меню в простом режиме показывает только «Диагностику» (N3, F3).

### P2 — полировка

- **P2-1. Sticky-шапка проекта:** при скролле остаётся узкая полоса «проект · поток · режим» (N4).
- **P2-2. Индикаторы заполненности в боковом меню** (точка/счётчик прогонов у этапа) — превращает меню в карту прогресса проекта.
- **P2-3. КПСЦ:** убрать дублирование итогов под картой (уже в data-box), починить наложение статуса на шапку карты, добавить кнопку «вписать по ширине» для широких карт.
- **P2-4. Tooltip-тур при первом входе (опционально):** 3–4 шага по боковому меню, показывается один раз, выключается навсегда; не блокирующий.

## 3. Что НЕ трогать

- **JS-мосты `__acUM`, `__acEE`, `__acData`, `__pzSkelet`** — все `id` полей, таблиц, кнопок, статус-строк и зон результатов сохраняются буквально; редизайн = CSS + обёртки + порядок раскрытия `<details>`, без переименований.
- **Контракты API** (эндпоинты расчёта, сохранения прогонов, истории) и форматы payload — без изменений.
- **Эталонная логика** расчётов (детекторы УМ, модель МР-09-2022, нотация КПСЦ, валидаторы SMART) и тексты методических формулировок в отчётах — не переписывать, не «упрощать».
- **Стек:** Flask + vanilla JS + SVG. Никаких фреймворков, сборщиков, UI-библиотек. Иконки бокового меню — inline SVG.
- Дизайн-токены `:root` (css 2–19) расширять, не заменяя: тёплая низконасыщенная палитра сохраняется.

## 4. Критерии приёмки редизайна (чек-лист)

**Навигация**
- [ ] Переход от «Поиска узкого места» к «ЭЭ-калькулятору» — 1 клик, без скролла.
- [ ] Текущий этап и активный проект видны на любом экране всегда (боковое меню + sticky-шапка).
- [ ] В «Простом старте» пользователь видит путь к полному режиму и понимает, что теряет/получает.

**Формы**
- [ ] ЭЭ-калькулятор в начальном состоянии показывает ≤ 12 полей на экране; остальное — под подписанными спойлерами.
- [ ] Все обязательные поля отличимы от необязательных без чтения легенды.
- [ ] Таблица операций: редактируемость ячеек видна сразу; навигация Enter/Tab работает; при 11 строках шапка не уезжает.

**Обратная связь и статусы**
- [ ] После изменения любого поля с пересчётом пользователь узнаёт об обновлении отчёта, даже если отчёт вне экрана (тост/кнопка «к отчёту»).
- [ ] Каждый статус имеет иконку + текст; ни один статус не передаётся только цветом.
- [ ] Наложение «СТАТУС: С ПРОБЕЛАМИ» на дату в шапке карты (skrin1) устранено.

**Помощь и пустые состояния**
- [ ] У каждого живого инструмента справка «?» ≤ 3 коротких абзацев + ссылка в методичку.
- [ ] Методичка открывается внутри приложения из бокового меню; из справки инструмента — переход в нужный раздел.
- [ ] Все 7 пустых состояний (таблица, история ×5, проект) содержат действие «с чего начать», а не пустое место.

**Регрессия**
- [ ] Прогон эталонных демо (ОКЗ, НОВОХРОМ, Оренбив) даёт бит-в-бит те же результаты, что до редизайна.
- [ ] Сохранение прогона, сравнение до/после, скачивание .md/.svg/.docx работают без изменений в JS-мостах.

**Полевой тест**
- [ ] Инженер 45+ без инструкции находит узкое место по демо-данным ≤ 3 минут; находит историю прогонов ≤ 30 секунд.
