## 1. Назначение и область применения {#ch1}

1.1. Настоящий документ является руководством пользователя веб-сервиса «Агент-цех» (далее — сервис). Сервис оцифровывает методологию ведения проекта по улучшению Федерального центра компетенций (ФЦК): маршрут МУ-65-2024 «Реализация проектов по улучшениям» от открытия проекта до протокола закрытия.

1.2. Сервис выполняет расчёты показателей по официальным формулам (МУ-66-2024 «Показатели проектов повышения производительности труда», МР-09-2022 «Оценка экономического эффекта от реализации мероприятий», редакция № 2) и формирует документы: пакет организационно-распорядительной документации (ОРД), разворот целей SMART, отчёт по узким местам потока создания ценности, карту потока создания ценности (КПСЦ), расчёт экономического эффекта (ЭЭ), справку ФЦК по форме 1.4, план мероприятий по шаблону Приложения № 4 МР «Решение проблем» и протокол выполнения мероприятий.

1.3. Все расчёты выполняются детерминированным расчётным ядром. Один и тот же набор входных данных всегда даёт один и тот же результат. Каждая итоговая величина в отчёте приводится с подстановкой значений в формулу. Результаты расчётов воспроизводимы и пригодны для представления на защите проекта.

1.4. Документ предназначен для консультантов региональных центров компетенций (РЦК), руководителей проектов предприятий и специалистов, выполняющих тестирование сервиса.

## 2. Системные требования {#ch2}

### 2.1. Системные требования

2.1.1. Для работы с сервисом требуется персональный компьютер с современным браузером (Chrome, Edge, Firefox, Safari актуальных версий). Установка дополнительного программного обеспечения на стороне пользователя не требуется.

2.1.2. Для открытия выгружаемых документов формата docx требуется редактор Word; для файла справки ФЦК формата xlsm — Microsoft Excel с разрешённым выполнением макросов (пересчёт итоговых значений выполняется Excel при открытии файла).

2.1.3. Адрес доступа к сервису и учётные данные направляются пользователю владельцем сервиса отдельным сообщением.

### 2.2. Учебные данные

2.2.1. В базе сервиса размещены учебные проекты («ОКЗ — экзамен волна 3», «Кушкуль — экзамен волна 3», «Тест интеграции в2» и др.). Данные учебных проектов обезличены и синтетичны; они предназначены для ознакомления с историей прогонов и сравнением. Рабочий проект создаётся отдельно (п. 4.1).

## 3. Обзор интерфейса {#ch3}

### 3.1. Режимы интерфейса

3.1.1. В шапке страницы расположен переключатель режимов **«Простой старт»** и **«Полный режим»**. Выбранный режим запоминается браузером; переключение не приводит к потере введённых данных.

3.1.2. Режим **«Простой старт»** открывается по умолчанию и содержит одну карточку — «Поиск узкого места» — с демо-кнопкой «ОКЗ (комбикорм)». Режим предназначен для первого ознакомления с сервисом. Кнопка **«Перейти к полному режиму»** открывает полный состав этапов и инструментов.

3.1.3. Режим **«Полный режим»** отображает боковое меню этапов проекта и все инструменты, описанные в разделе 5.

### 3.2. Боковое меню этапов

3.2.1. В левой части экрана расположено боковое меню этапов проекта по маршруту МУ-65: «0. Предстарт», «1. Открытие», «2. Диагностика», «3. Цель и план», «4. Внедрение», «5. Закрытие», а также пункт **«Помощь»**. Каждый пункт снабжён иконкой и краткой подсказкой о содержании этапа.

3.2.2. Щелчок по пункту меню открывает соответствующий этап; на экране одновременно отображается один этап. У пунктов меню отображаются бейджи с числом сохранённых прогонов по инструментам этапа (при выбранном проекте).

3.2.3. Пункт **«Помощь»** открывает встроенную методичку пользователя (настоящий документ в сокращённом виде) со ссылками на разделы по каждому инструменту.

### 3.3. Общие правила работы карточек инструментов

3.3.1. **Автоматический пересчёт.** В инструментах «Поиск узкого места», «Цели SMART», «ЭЭ-калькулятор» отчёт пересчитывается автоматически через полсекунды после изменения любого поля. Отдельная кнопка «Рассчитать» отсутствует.

3.3.2. **Пустое поле — отсутствие данных, а не ошибка.** Инструмент рассчитывает показатели, для которых достаточно введённых данных; недостающие данные перечисляются в блоке «домерить». Подстановка нулевых значений не выполняется.

3.3.3. **Валидация ввода.** Ячейка с нечисловым значением подсвечивается красным («не число») и блокирует пересчёт с перечнем проблем (например: «строка 3, колонка "Тц, мин": "двадцать" — не число»). Незаполненная обязательная ячейка подсвечивается янтарным («не заполнено»). Допускаются десятичная запятая и пробелы-разделители разрядов.

3.3.4. **Плашка «отчёт устарел».** Если после получения отчёта введённые данные изменены так, что расчёт стал невозможен (не исправлены подсвеченные ячейки), область отчёта приглушается и отображается плашка «Отчёт устарел — исправьте подсвеченные данные, отчёт пересчитается автоматически».

3.3.5. **Подтверждение демо-данных.** Если в форме имеются введённые пользователем данные, нажатие демо-кнопки вызывает запрос подтверждения («Заменить введённые данные демо-примером?»). При отмене введённые данные сохраняются.

3.3.6. **Предупреждение при закрытии.** При закрытии вкладки с несохранённым вводом браузер выводит предупреждение. Автоматическое сохранение черновика не предусмотрено; перед завершением работы сохраните прогон (раздел 6).

## 4. Базовые понятия: проект, прогон, метка, контекст {#ch4}

### 4.1. Проект

4.1.1. Проект — запись в базе сервиса: название, предприятие, пилотный поток создания ценности. Создаётся кнопкой **«Новый проект»** в шапке страницы. Обязательным является только название; поля «предприятие» и «поток» следует заполнить при создании, поскольку они используются проверками контекста (п. 4.4).

4.1.2. Текущий проект выбирается в выпадающем списке шапки; выбор запоминается браузером. Индикатор в шапке отображает «Проект: название · предприятие · поток» либо «проект не выбран».

4.1.3. Без выбранного проекта доступны все расчёты; недоступны сохранение прогонов, история, сравнение и автоматическая подстановка данных между инструментами.

### 4.2. Прогон

4.2.1. Прогон — сохранённый в проекте расчёт одного инструмента: входные данные, отчёт, ключевые итоги, автор, дата, комментарий. Сохранение выполняется кнопкой **«Сохранить прогон в проект»**, имеющейся в каждом инструменте.

4.2.2. При сохранении браузер передаёт на сервер только входные данные; сервер повторно выполняет расчёт через расчётное ядро и сохраняет результат. Подмена итоговых значений исключена.

4.2.3. Прогон является неизменяемым: редактирование и удаление не предусмотрены. При ошибочном вводе создайте новый прогон с поясняющим комментарием (например: «перезамер, исправлен Тц дозирования»). История проекта ведётся по принципу лабораторного журнала.

### 4.3. Метки «до» и «после»

4.3.1. При сохранении прогона ему может быть присвоена метка **«до»** или **«после»** (либо прогон сохраняется без метки). Метки используются при сравнении и при подстановке данных: например, в протокол закрытия экономический эффект подставляется из самого свежего прогона ЭЭ-калькулятора; если этот прогон не имеет метки «после», сервис выводит соответствующее предупреждение.

4.3.2. Пример применения: в марте сохранён прогон диагностики с меткой «до»; в июне, после внедрения мероприятий, сохранён повторный замер с меткой «после». Отметьте оба прогона в истории и нажмите «Сравнить до/после» — будет сформирован дельта-отчёт об изменении узкого места, долей ВПП и производительности.

### 4.4. Контекст

4.4.1. Контекст — пара «предприятие · поток». Сервис предотвращает смешение данных разных потоков создания ценности:

- если при сохранении прогона предприятие или поток во входных данных расходятся с карточкой проекта, прогон сохраняется с пометкой «контекст расходится» и предупреждением;
- при автоматической подстановке (в ЭЭ-калькулятор и протокол закрытия) значения из прогонов другого потока не подставляются; сервис выводит объяснение отказа;
- если форма начата при одном проекте, а сохранение выполняется в другой, отображается запрос подтверждения «Данные вводились для другого контекста. Сохранить?».

4.4.2. Правило организации работы: один проект — один поток. Различные потоки одного предприятия ведутся отдельными проектами.

### 5.0. Отбор предприятия и выбор пилотного потока (этап «Предстарт») {#ch50}

5.0.1. Инструмент «Отбор предприятия» воспроизводит механику отбора по МР-15-2026, редакция № 5 от 28.07.2026: формальная проверка (п. 3.4, пять вопросов «да/нет»), чек-лист очного отбора и скоринг-карта (md). Чек-лист выбирается переключателем трека: РЦК — 30 пунктов Приложения № 5, ФЦК — 28 пунктов Приложения № 4; каждый пункт — 1 балл, порог рекомендации единый — 18 (п. 3.7). Пункты со «*» — отсекающие (РЦК: 1.1, 1.2, 1.4, 3, 4; ФЦК: 1.1, 1.2, 1.3, 1.5, 3) — отклоняют предприятие независимо от суммы баллов; при смене трека ответы чек-листа сбрасываются, вердикт и скоринг-карта содержат указание трека.

5.0.2. Инструмент «Выбор пилотного потока» сравнивает 1–3 кандидатных потока: 5 критериев потока (доля в выручке ≥ 10 % — обязательный критерий; цикл ≤ 1 месяца; потенциал роста продаж; план производства и продаж; самостоятельность в сбытовой политике) и карта из 15 признаков потерь (пп. 6.2–6.16 Прил. № 5). Каждое «да» и каждый отмеченный признак — 1 балл (максимум 20); рекомендуется кандидат с наибольшим итогом, скоринг-карта содержит обоснование. По МР выбор потока подтверждается обходом в ходе очного отбора (Прил. № 3, шаг 3).

5.0.3. Прогоны обоих инструментов сохраняются в проект кнопкой «Сохранить прогон в проект» (неизменяемый снапшот, сервер пересчитывает вход) и сравниваются «до/после».

5.1.1. Инструмент формирует один файл Word: приказ о назначении ответственных за реализацию мероприятий (приложение № 2 МУ-65) и карточку проекта. Незаполненное поле отображается в документе как «___» и включается в перечень «домерить».

5.1.2. Порядок заполнения полей:

| Поле | Содержание | Источник данных |
|---|---|---|
| Предприятие, город, пилотный поток | Реквизиты заказчика | Карточка проекта (подставляется автоматически при выбранном проекте) |
| Приказ: номер, дата, нацпроект | Номер и дата приказа предприятия | ОРД предприятия; нацпроект по умолчанию «Производительность труда» |
| Руководитель: должность, ФИО | Подписант приказа | Штатное расписание |
| Ответственные (таблица) | Роль, должность, ФИО, телефон, почта — строка на человека | Распоряжение о команде проекта |
| Проект: название, ключевой риск, второстепенные риски | Каждый второстепенный риск — с новой строки | Материалы стартового совещания |
| Ключевые события | Даты ДД.ММ.ГГГГ: старт, диагностика с/по, совещание, внедрение с/по, закрытие | План-график; по МР-08 — окно 19–28 недель |
| Цели (таблица) | Наименование, текущий / целевой / идеальный уровни | Кнопка «Подтянуть из последнего прогона SMART» (после заполнения п. 5.2) |
| Вовлечённые лица и рамки | Клиенты процесса, периметр, границы, владелец процесса, руководитель проекта | Карта процесса, стартовое совещание |
| Команда проекта | Каждый участник с новой строки: ФИО (должность) | Приказ о команде |

5.1.3. Кнопки: **«Сформировать пакет (docx)»** — документ скачивается немедленно; **«Сохранить прогон в проект»** — пакет дополнительно помещается в историю проекта (скачивание docx из истории — по ссылке «скачать docx»). Рекомендуемая последовательность: заполнить SMART, выполнить подстановку целей в ОРД, сформировать docx.

### 5.2. Цели SMART (этап «Открытие») {#ch52}

5.2.1. Инструмент формирует цели проекта по SMART (МУ-65, п. 4.1.5) с методикой расчёта каждого показателя по МУ-66-2024.

5.2.2. Порядок работы:

1. Выберите рамку производительности труда: федеральную (+5 %/год, 15 % к третьему году) или региональную (+10/15/30 %).
2. Добавьте цели кнопкой **«+ цель»** и заполните поля каждой цели по таблице ниже.
3. Проверьте разворот целей S/M/A/R/T и флаги валидаторов под формой.
4. Сохраните прогон.

| Поле | Содержание | Источник данных |
|---|---|---|
| Наименование цели | Например, «Выработка, шт. в мес.» | Дерево целей проекта |
| Показатель МУ-66 | Выбор из встроенного справочника; «авто» — подбор по наименованию | Справочник МУ-66-2024 |
| Ед. изм., текущий, целевой, идеальный | Значения показателя | Замеры базовой линии; целевой уровень — по рамке ПТ |
| Срок (T), горизонт (1–3 года), направление | Дата достижения; «рост» или «снижение» (по умолчанию — из справочника) | План-график |
| Методика расчёта, источник, периодичность | Подставляются из МУ-66 в пустые поля; допускается редактирование | Справочник; корректируется под практику предприятия |

5.2.3. Валидаторы сигнализируют о следующих условиях: измеримость (наличие чисел и единиц), порог достижимости 30 % (превышение целью текущего уровня более чем на 30 % требует обоснования), наличие обязательного показателя проекта из МУ-66, соответствие рамке ПТ. Флаги не блокируют сохранение; статус отображает «флагов валидаторов: N». Сохранённый прогон SMART является источником целей для пакета ОРД и показателей для протокола закрытия.

### 5.3. Поиск узкого места (этап «Диагностика») {#ch53}

5.3.1. Инструмент определяет узкое место потока создания ценности по четырём независимым детекторам: время цикла (Тц); темп потока (минимальная производительность); доля во времени производственного цикла (ВПП; первый эшелон ≥ 25 %, второй ≥ 10 %); переделка (возврат, %). Главным узким местом признаётся кандидат, подтверждённый не менее чем двумя детекторами; при подтверждении одним детектором отчёт содержит указание «слабое подтверждение — домерить».

5.3.2. Общие поля потока (все необязательны; такт и спрос разблокируют дополнительные блоки отчёта):

| Поле | Содержание | Источник данных |
|---|---|---|
| Поток / проект | Название потока | Карточка проекта |
| Персонал, чел. | Численность на потоке | Лист производственного анализа (ПА) |
| ВПП итого, сек | Полное время производственного цикла | Карта текущего состояния |
| Спрос, шт/период | Потребность периода | План продаж / заказы |
| Доступное время, мин | Фонд времени периода | Режим работы |
| Такт, мин | Требуемый темп | Доступное время ÷ спрос (или из карты) |

5.3.3. Таблица операций: поля **Операция** и **Тц, мин** обязательны; поля **Произв., т/ч**, **ВПП, сек**, **Возврат, %** заполняются при наличии данных. Пустая ячейка означает отсутствие данных.

5.3.4. Предусмотрены четыре способа ввода данных (вкладки над таблицей):

1. **Таблица** — ручной построчный ввод; кнопка «+ строка» добавляет строку, «×» удаляет.
2. **Вставить из Excel** — скопируйте диапазон в Excel и вставьте (Ctrl+V) в поле. Порядок колонок: операция · Тц · производительность · ВПП · возврат; разделитель — табуляция или «;». Строки-заголовки отбрасываются автоматически. Результат помещается в таблицу первой вкладки, где подлежит проверке.
3. **Файл JSON** — служебный способ: полный файл по спецификации № 1 (содержит поля, отсутствующие в таблице: запасы в денежном выражении, точечные замеры). Применяется для обмена данными между прогонами.
4. **Файл Excel (.xlsx)** — разметка реальных листов ПА и карт. Загрузите файл (до 20 МБ; формат .xls предварительно пересохраните как .xlsx). Сервис отображает превью первых 30 строк × 20 колонок с координатами ячеек (объединённые ячейки подсвечены; значение читается только из главной ячейки). Укажите:
   - расположение операций: **в строках** (строка = операция; поля задаются буквами колонок) или **в столбцах** (столбец = операция, как в карте КПСЦ; поля задаются номерами строк);
   - расположение названия операции (обязательно), Тц, производительности, ВПП, возврата;
   - начальную и конечную строку/столбец данных (пустое значение — до конца, не более 500 позиций);
   - единицы Тц (минуты или секунды; секунды пересчитываются).
   Нажмите **«Применить разметку»**. Нечисловые ячейки пропускаются с перечнем предупреждений. Разметка запоминается браузером для данного файла и листа; при повторной загрузке того же файла доступна кнопка «Применить сохранённую разметку». Загруженный файл хранится в памяти сервера один час; по истечении отображается «сессия файла истекла» — загрузите файл повторно.

5.3.5. Кнопка **«Демо: ОКЗ (комбикорм)»** заполняет форму учебным набором данных (при наличии введённых данных запрашивается подтверждение замены).

5.3.6. Результат: плашка «Главное узкое место» (наименование операции, подтверждение детекторами, масштаб в часах и доле ВПП, три приоритетных пункта «домерить») и отчёт: базовые параметры (такт, ΣТц, число рабочих мест), ранжированные узкие места с цифровым доказательством и типом потери, дисбаланс потока (правило 5 %), расчёты с подстановкой в формулы, полный перечень «домерить». Отчёт скачивается кнопкой **«Скачать .md»**; прогон сохраняется с меткой и комментарием.

### 5.4. Карта потока создания ценности, КПСЦ (этап «Диагностика») {#ch54}

5.4.1. Карточка «Карта потока (КПСЦ)» строит карту потока создания ценности по данным таблицы операций инструмента «Поиск узкого места» (п. 5.3); повторный ввод не требуется.

5.4.2. Порядок работы:

1. Заполните таблицу операций в карточке «Поиск узкого места» любым способом (п. 5.3.4).
2. Нажмите кнопку **«Построить карту»** — карта отобразится на экране.
3. При выполненном расчёте узкого места главное узкое место отмечается на карте знаком «звезда».
4. Проверьте итоги под картой:
   - **Σ времени ценности** — суммарное время операций, создающих ценность;
   - **Σ потерь** — суммарное время потерь;
   - **ВПП** — полное время производственного цикла;
   - **доля ценности** — отношение времени ценности к ВПП, в процентах.
5. Нажмите **«Скачать .svg»** для сохранения карты в векторном формате (файл открывается браузером и вставляется в презентации и отчёты без потери качества).

5.4.3. Ограничение версии: карта строится только для линейного потока — последовательности операций без ветвлений и параллельных линий (п. 9.1).

### 5.5. ЭЭ-калькулятор (этап «Цель и план») {#ch55}

5.5.1. Инструмент рассчитывает экономический эффект проекта по официальной модели ФЦК (МР-09-2022, редакция № 2). Рамки методики: условный год, цены «до», суммы без НДС, контур — концевой серийный поток. Расчётное ядро проверено на модельных эталонах корпуса разборов (НОВОХРОМ, Строгонов, Оренбив, Атэна).

5.5.2. Подготовительные действия: выберите проект в шапке и нажмите **«Контекст диагностики проекта»** — подставляются предприятие и поток; ниже отображается подсказка: главное узкое место по последнему прогону диагностики и производительности операций. Экономические величины (цена, себестоимость, объём, такт) вводятся из экономических данных проекта. Демо-кнопки **«Демо: НОВОХРОМ»** и **«Демо: Оренбив»** заполняют форму обезличенными экзаменационными данными.

Незаполненные обязательные поля подсвечиваются янтарным и блокируют расчёт. Остальные поля сгруппированы под раскрывающимися спойлерами и заполняются при наличии данных:

### 5.6. План мероприятий (этап «Цель и план») {#ch56}

5.6.1. **Назначение.** Инструмент превращает находки диагностики в обоснованный и квантифицированный план мероприятий по шаблону Приложения № 4 МР «Решение проблем». Методологическая опора: МР «Решение проблем», МУ-65-2024, Приложения № 4, 6 (оценка рисков) и № 8 («Матрица приоритезации проблем»).

5.6.2. **Когда применять.** Инструмент применяется после выполненной диагностики (пп. 5.3–5.4), когда главное узкое место определено, при подготовке к совещанию по решению проблем и защите целевой карты (МР-08, 2.3). Инструмент подбирает мероприятия-кандидаты и их расчётную оценку; итоговый состав плана утверждает рабочая группа проекта (п. 5.6.8).

5.6.3. **Входные данные.** Обязательные поля (отмечены знаком «*»): участок / узкое место; ВПП факт, %; разрыв от нормы, п.п.; Тцикл узкого места, мин; длительность смены, мин (по умолчанию 480). Поля заполняются по последнему прогону диагностики; поле «Норма ВПП, %» задаётся при отклонении нормы от типовой (15 %).

| Секция | Поля | Источник данных |
|---|---|---|
| Проблема (узкое место) | Предприятие; участок / узкое место; ВПП факт, %; разрыв от нормы, п.п.; норма ВПП, %; Тцикл узкого места, мин; смена, мин; замер простоев оборудования, мин/смену | Последний прогон диагностики; хронометраж / фотография рабочего дня (факт-замер повышает доказанность цепочки причин) |
| Признаки потерь на участке | 15 признаков (пп. 6.2–6.16 Прил. № 5 МР-15-2026): отмечаются только подтверждённые обходом; каждый разворачивается в ветку дерева потерь | Обход участка, лист производственного анализа |
| Экономика потока (спойлер) | Такт (требуемый), мин; цена единицы без НДС, руб; переменная с/с единицы без НДС, руб; фонд времени (смен/сутки, часов/смену, дней/год); флажок «спрос превышает возможности» | Диагностика (такт); управленческий учёт (цена, с/с); режим работы (фонд) |
| Оформление плана | Ответственный за мероприятия; дата начала плана | Распоряжение о команде; план-график. Пустой ответственный — «назначается на совещании по решению проблем»; пустая дата — авто-предложение по классу трудоёмкости (помечается как допущение) |

5.6.4. **Порядок работы:**

1. Заполните секцию «Проблема» по последнему прогону диагностики.
2. Отметьте подтверждённые обходом признаки потерь.
3. При наличии экономических данных раскройте спойлер «Экономика потока» и заполните поля — это разблокирует расчёт ΔЭЭ (без секции мероприятия ранжируются по ΔВПП).
4. Заполните секцию «Оформление плана» и нажмите **«Сформировать план»**.
5. Проверьте сводку и топ-5 мероприятий; кнопкой **«Показать рассуждение»** раскройте полную цепочку расчёта и обоснований.
6. Скачайте план кнопками **«Скачать .docx»** и **«Скачать .xlsx»**; сохраните прогон кнопкой **«Сохранить прогон в проект»**.

5.6.5. **Цепочка расчёта** (воспроизводит логику МР «Решение проблем»): проблема формулируется по правилу ФЦК (факт, где, сколько — разрыв, последствие) → симптом раскладывается в дерево потерь по отмеченным признакам и 7 видам потерь (Приложение № 1 «Виды потерь») → по каждой ветке определяются коренные причины (метод 5 почему; при необходимости — диаграмма Исикавы по 6М: человек, машина, материал, метод, измерение, среда) → из библиотеки инструментов бережливого производства подбираются мероприятия (SMED, пока-йоке, 5С, канбан, выравнивание производства, стандартизированная работа и др.); у каждого инструмента указан электронный курс «Академии производительности» для обучения исполнителей.

5.6.6. **Квантификация и приоритизация.** Каждое мероприятие сопровождается расчётными дельтами: ΔВПП (п.п.), Δвремени цикла, Δвыработки, Δпроизводительности труда и — при заполненной секции «Экономика» — Δэкономического эффекта по МР «Оценка экономического эффекта» редакции № 4 (расчёт выполняется связкой с ЭЭ-калькулятором, без дублирования логики). Сумма ΔВПП мероприятий нормируется к разрыву узкого места и не превышает его. Приоритет присваивается по Матрице приоритезации (Прил. № 8, эффект × трудоёмкость): класс A — выполнять первыми, далее классы B и C; сроки предлагаются по классу трудоёмкости. Каждое мероприятие сопровождается оценкой рисков по структуре Прил. № 6 МУ-65-2024.

5.6.7. **Что на выходе и как читать результат.** На экране: сводка плана (число мероприятий, суммарные ΔВПП/Δвыработки/ΔЭЭ), топ-5 мероприятий с классом приоритета и цепочка обоснования. Каждый факт цепочки имеет класс доказанности: **«факт»** (подтверждён замером или прогоном диагностики), **«допущение»** (нормативная оценка), **«нужен замер»** (данных нет — указан рекомендуемый инструмент замера: хронометраж, фотография рабочего дня, почасовой производственный анализ). Ветки с меткой «нужен замер» подлежат подтверждению до включения соответствующих мероприятий в утверждаемый план. Файлы: план по шаблону Приложения № 4 в форматах docx и xlsx (с итоговой строкой Σ дельт и ссылками на курсы). Прогон сохраняется в проект с меткой и комментарием по общим правилам (раздел 6).

5.6.8. **Типовые ошибки и оговорки.**

- Оценка носит расчётный характер: дельты показателей — это плановая оценка эффекта, а не гарантированный результат; факт подтверждается замером «после».
- Часть диапазонов ΔВПП — нормативные допущения из типовых диапазонов библиотеки инструментов; они помечаются классом «допущение» и подлежат уточнению замерами на участке.
- Отмечайте только те признаки потерь, которые подтверждены обходом: отметка «на всякий случай» раздувает дерево потерь и снижает доказанность плана.
- Без заполненной секции «Экономика» ΔЭЭ не рассчитывается, и ранжирование выполняется только по ΔВПП — это не ошибка, а неполный ввод.
- Не оставляйте в плане мероприятия с классом доказанности «нужен замер» без выполненного замера.
- Итоговые решения о составе, сроках и ответственных принимает руководитель проекта; инструмент формирует обоснованное предложение, а не утверждённый документ. План подлежит обсуждению на совещании по решению проблем и утверждению в установленном порядке.

### 5.7. Протокол закрытия (этап «Закрытие») {#ch57}

5.7.1. Инструмент формирует «Протокол выполнения мероприятий по Соглашению» (приложение № 6, мероприятие 0.6 МР-08) — документ Word с реквизитами, показателями, приложением № 1 (результаты мероприятий) и приложением № 2 (чек-лист «21 балл»). Незаполненное поле отображается как «___» и включается в перечень «домерить» в конце docx.

5.7.2. Порядок работы:

1. Выберите проект в шапке и нажмите **«Подтянуть данные проекта»**. Подставляются: предприятие и поток из карточки проекта; ЭЭ (руб/год) из самого свежего прогона ЭЭ-калькулятора; показатели «до/цель» из последнего прогона SMART (факт — замер «после» — заполняется вручную); подсказка отображает главное узкое место из диагностики. Подстановка выполняется с проверкой контекста: значение из прогона другого потока не подставляется, выводится предупреждение с объяснением. Явно введённое пользователем значение имеет приоритет: подставляются только пустые поля.
2. Заполните поля по таблице ниже.
3. Заполните приложение № 1 и приложение № 2 (пп. 5.7.3, 5.7.4).
4. Нажмите **«Сформировать протокол (docx)»** и **«Сохранить прогон в проект»**.

| Блок | Содержание |
|---|---|
| Реквизиты | Предприятие, РЦК, номер и дата Соглашения, период реализации, место и дата подписания, поток ключевого продукта |
| Подписанты | Должность и ФИО от предприятия и от РЦК |
| Показатели потока | Таблица: показатель, ед. изм., до проекта / цель / факт |
| Открытые проекты и их цели | Таблица по структуре программы (ВПП, запасы, выработка, дополнительный показатель) |
| Цели по ПТ и ЭЭ | Прирост ПТ к базовому году и к третьему году, %; экономический эффект, руб/год (подставляется) |
| Лучшие практики | Каждая практика с новой строки |

5.7.3. **Приложение № 1 — мероприятия.** Таблица формируется из официального скелета протокола; для каждого мероприятия выберите «Выполнено / Не выполнено / — не заполнять —». Переключатель «По умолчанию» проставляет значение всем строкам. Строки-разделы, выделенные жирным, результата не требуют.

5.7.4. **Приложение № 2 — чек-лист «21 балл».** Чек-лист содержит 14 направлений развития производственной системы с оценкой 0–3 по каждому; порог зачёта — 21 балл. Режимы ввода:

- **«Только баллы» (быстрый)** — балл проставляется по каждому направлению вручную; применяется для черновой оценки;
- **«По требованиям» (официальная форма)** — оценивается каждое требование: «Соответствует / Не соответствует / Н/П» («не применимо» не блокирует), с комментарием. Баллы направлений рассчитываются автоматически по методике уровней: уровень 1 засчитывается при выполнении всех его требований; уровень 2 — при полном уровне 1 и т. д.; оценка «Не соответствует» останавливает рост уровня. Режим рекомендуется для подписного документа, поскольку воспроизводит официальный чек-лист оценки 4.0.

5.7.5. Строка «Итого: X / 21» пересчитывается автоматически: при неполном заполнении отображается «заполнено N из 14», при полном — вердикт «порог пройден / НЕ пройден». Недооценённые направления в итог не включаются и попадают в перечень «домерить».

5.7.6. При неположительном значении ЭЭ документ формируется с выделенной пометкой-предупреждением; в этом случае проверьте входные данные. Формулировка нацпроекта в шапке шаблона соответствует редакции 2022 года; для проектов 2025 года и позднее скорректируйте её вручную в готовом docx.

## 6. Работа с проектом: сохранение, загрузка, сравнение прогонов {#ch6}

6.1. При выбранном проекте в каждой карточке инструмента отображается блок **«История прогонов проекта»**: таблица «№, дата, метка, итог одной строкой, автор, комментарий».

6.2. **Загрузка прогона в форму.** Кнопка **«→ в форму»** загружает входные данные выбранного прогона обратно в форму. Это основной сценарий замера «после»: загрузите прогон «до», введите новые замеры, сохраните результат новым прогоном; исходный прогон остаётся неизменным.

6.3. При выборе проекта последний прогон каждого инструмента подгружается в форму автоматически, если форма не редактировалась пользователем. Если в форму введены данные, автоматическая подгрузка не выполняется; отображается кнопка-подсказка «Загрузить последний прогон».

6.4. **Сравнение «до/после»** предусмотрено для трёх инструментов: «Поиск узкого места», «ЭЭ-калькулятор», «Цели SMART». Отметьте ровно два прогона и нажмите **«Сравнить до/после»**; прогоном «до» считается более ранний по номеру. Дельта-отчёт для диагностики содержит: изменение главного узкого места и его причины (сработавшие детекторы в обоих прогонах), изменение долей ВПП в процентных пунктах, изменение производительности и мест в ранжировании. Для ЭЭ — изменения четырёх ключевых сумм. Для SMART — уточнение целей. При различии состава операций сравнение помечается «частичным»; операции с одинаковыми наименованиями сопоставляются по порядковому номеру экземпляра (#1, #2). Сравнение прогонов разных инструментов не выполняется; сервис отказывает с поясняющим сообщением.

6.5. **Типовой сквозной сценарий проекта:**

1. Создайте проект («Новый проект»: название, предприятие, пилотный поток).
2. Этап «Открытие» → «Цели SMART»: задайте рамку ПТ и 3–5 целей; сохраните прогон.
3. Этап «Открытие» → «Пакет ОРД» → «Подтянуть из последнего прогона SMART» → заполните реквизиты → «Сформировать пакет (docx)» → «Сохранить прогон».
4. Этап «Диагностика» → «Поиск узкого места»: загрузите лист ПА (вкладка «Файл Excel (.xlsx)»), выполните разметку, проверьте таблицу; сохраните прогон с меткой **«до»**.
5. Этап «Диагностика» → «Карта потока (КПСЦ)» → «Построить карту» → «Скачать .svg».
6. Этап «Цель и план» → «ЭЭ-калькулятор» → «Контекст диагностики проекта» → заполните секции, укажите ключевую ставку ЦБ → сохраните прогон (комментарий «плановый ЭЭ»); при необходимости выгрузите справку ФЦК.
7. Этап «Цель и план» → «План мероприятий»: заполните секцию «Проблема» по прогону диагностики, отметьте подтверждённые признаки потерь, заполните секцию «Экономика» → «Сформировать план» → проверьте топ-5 и цепочку («Показать рассуждение») → «Скачать .docx» / «Скачать .xlsx» → сохраните прогон.
8. Этап «Внедрение» в текущей версии не оцифрован; реализацию утверждённого плана ведите в рабочих формах предприятия.
9. Замер «после»: история диагностики → «→ в форму» у прогона «до» → введите новые замеры → сохраните с меткой **«после»** → отметьте оба прогона → «Сравнить до/после». При необходимости выполните фактический расчёт ЭЭ вторым прогоном.
10. Этап «Закрытие» → «Протокол закрытия» → «Подтянуть данные проекта» → заполните реквизиты, факты показателей, приложения → проверьте «Итого: X / 21» → «Сформировать протокол (docx)» → «Сохранить прогон».

## 9. Ограничения текущей версии {#ch9}

9.1. **КПСЦ — только линейный поток.** Карта потока создания ценности строится для последовательности операций; ветвления, параллельные линии и возвратные петли на карте не отображаются.

9.2. **Справка ФЦК — ветка «концевой серийный поток».** ЭЭ-калькулятор и выгрузка справки по форме 1.4 действуют только для концевого серийного потока и только по МР-09-2022 редакции № 2. Полуфабрикатная и позаказная ветки, мультипродукт, редакция № 4 (МР-13-2025), NPV и окупаемость находятся вне контура. Для другого типа потока сервис возвращает отказ, а не приближённое значение.

9.3. **Адрес доступа может обновляться.** При недоступности адреса запросите актуальный у владельца сервиса. Учётные данные являются демонстрационными и подлежат замене при промышленном запуске.

9.4. **Учебные данные обезличены.** Демонстрационные наборы («ОКЗ», «НОВОХРОМ», «Оренбив» и др.) являются синтетическими и предназначены исключительно для обучения и тестирования.

9.5. **Пакетная загрузка листов ПА не предусмотрена.** Вкладка Excel выполняет разметку и извлечение таблицы операций из одного файла за сеанс (кэш на сервере — один час, в памяти — до пяти книг).

9.6. **Учётные записи отсутствуют.** На внешний адрес действует один общий логин; поле «автор» прогона — свободный текст (по умолчанию «РЦК»). Разграничение прав не предусмотрено: любой пользователь, имеющий доступ к сервису, видит все проекты в общей базе.

9.7. **Часть этапов не оцифрована.** На этапе «Предстарт» действуют инструменты «Отбор предприятия» (оба трека — РЦК и ФЦК) и «Выбор пилотного потока»; на этапе «Цель и план» действует инструмент «План мероприятий»; ранжирование потоков, форма № 4, трекер статусов плана и инструменты этапа «Внедрение» помечены «В разработке» и являются заглушками плана развития.

9.8. **Автосохранение черновика отсутствует.** Обновление страницы без сохранения прогона приводит к потере введённых данных (браузер выводит предупреждение).

9.9. **Сравнение прогонов ранних редакций ограничено.** Прогоны, сохранённые до редакции v1.1, не содержат перечня сработавших детекторов; в дельта-отчёте доступна только арифметика. Для полной интерпретации пересохраните прогоны заново.

9.10. **Мероприятия формируются как расчётное предложение.** Инструмент «План мероприятий» подбирает мероприятия из библиотеки инструментов ФЦК и оценивает их эффект расчётным путём; часть оценок основана на нормативных допущениях (п. 5.6.8). Окончательный состав плана, сроки и ответственные определяются рабочей группой и утверждаются руководителем проекта.

## 10. Порядок проведения тестирования {#ch10}

10.1. **Цель тестирования** — независимая проверка настоящей методички и сервиса методологом, не участвовавшим в разработке: соответствие инструкций фактическому поведению интерфейса v2.2, полнота и понятность формулировок, выявление расхождений с практикой ведения проектов.

10.2. **Условия.** Тестирование выполняется по адресу и учётным данным, направленным владельцем сервиса (п. 2.1.3). Допускается использование учебных проектов и демо-данных; ввод реальных данных предприятий не требуется. Ориентировочная продолжительность — 60–90 минут.

10.3. **Сценарии теста** (выполняйте последовательно, фиксируя результат по каждому заданию: «выполнено / не выполнено / замечание»):

1. **Вход и навигация.** Войдите по внешней ссылке. Переключитесь из режима «Простой старт» в «Полный режим». Откройте по боковому меню этапы «Диагностика» и «Помощь». Убедитесь, что на экране отображается один этап, а «Помощь» содержит методичку.
2. **Поиск узкого места по демо-данным.** В карточке «Поиск узкого места» нажмите «Демо: ОКЗ (комбикорм)». Убедитесь, что появилась плашка «Главное узкое место» (операция «фасовка») и отчёт с расчётами. Проверьте валидацию: введите текст в числовую ячейку (красная подсветка) и очистите обязательную ячейку (янтарная подсветка, плашка «отчёт устарел»).
3. **Построение КПСЦ.** Не изменяя данные таблицы, нажмите «Построить карту» в карточке «Карта потока (КПСЦ)». Убедитесь, что узкое место отмечено звездой, итоги (Σ времени ценности, Σ потерь, ВПП, доля ценности) отображены. Скачайте карту кнопкой «Скачать .svg» и откройте файл.
4. **Расчёт экономического эффекта.** В карточке «ЭЭ-калькулятор» нажмите «Демо: НОВОХРОМ». Убедитесь, что отображены четыре итоговые величины (реальный ЭЭ, потенциальный ЭЭ, высвобождение, налоги за 3 года) и что факторная декомпозиция сходится. Ознакомьтесь с расшифровками метрик (знак «?» у полей).
5. **Выгрузка справки ФЦК.** Нажмите «Скачать справку ФЦК». Убедитесь, что скачан файл .xlsm с именем «1.4 Справка_ЭЭ_…». Откройте файл в Excel и проверьте, что поля заполнены данными формы, а итоговые значения пересчитались при открытии.
6. **Работа с проектом.** Создайте новый проект (название, предприятие, поток). Сохраните прогон диагностики с меткой «до». Нажмите «→ в форму» у сохранённого прогона, измените один замер, сохраните второй прогон с меткой «после». Отметьте оба прогона и нажмите «Сравнить до/после» — убедитесь, что сформирован дельта-отчёт.
7. **Протокол закрытия.** Откройте «Протокол закрытия», нажмите «Подтянуть данные проекта». Проверьте, что подставленные значения соответствуют прогонам проекта. Заполните несколько направлений чек-листа «21 балл» в режиме «по требованиям» и проверьте пересчёт строки «Итого: X / 21».

10.4. **Форма обратной связи.** По итогам тестирования заполните письменный отзыв по следующим вопросам:

1. Какие разделы или формулировки методички непонятны либо требуют пояснения?
2. Что в поведении сервиса не совпало с Вашей практикой ведения проектов по МУ-65/МР-08?
3. Какие задания сценария не были выполнены и по какой причине (что именно не сработало, текст сообщения об ошибке)?
4. Каких функций или данных не хватает для применения сервиса в Ваших закрытых проектах?
5. Оцените по шкале 1–5: понятность методички; соответствие интерфейса инструкциям; готовность к самостоятельному применению.

10.5. Замечания оформляются с указанием раздела методички и номера задания сценария. Отзыв направляется в порядке, установленном приложением А.

## Приложение А. Порядок обратной связи и контакты {#chA}

А.1. Вопросы по работе сервиса, замечания к настоящей методичке и результаты тестирования направляются владельцу сервиса (ИИ-направление проекта «Агент-цех») по рабочим каналам связи проекта.

А.2. Обращение должно содержать: дату; редакцию методички (3.1) и версию интерфейса (v2.2); раздел методички или наименование инструмента; описание ситуации с текстом сообщения сервиса (при наличии); ожидаемый результат.

А.3. Запросы на актуальный адрес доступа и учётные данные направляются владельцу сервиса отдельным обращением (п. 2.1.3).

А.4. Настоящая методичка подготовлена по исходному коду сервиса (app.py, index.html, контракт данных, спецификации № 1 и № 2). При изменении версии сервиса проверяйте соответствие описанных экранов и сообщений.
